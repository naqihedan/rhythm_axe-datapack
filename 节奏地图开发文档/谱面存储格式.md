# 谱面存储格式

这里只介绍谱面的存储格式，若要查看谱面如何运行或编辑，见[开始游戏](游玩谱面.md#开始游戏)和[编辑器](编辑器.md#编辑器)。

一张谱面的全部数据存放在命令存储 `rhythm_axe:maps.<mapid>` 下，其中 `<mapid>` 替换为谱面的标识符（如 `new_beginning`）。编辑器读取此 NBT 后整合为可编辑的形式，"读取器"则将其运行为可玩的谱面。

## 谱面数据值

### NBT 结构

> 图例：<code>{ }</code> = 复合标签（对象）　<code>[ ]</code> = 列表/数组　<code>[]</code> = 字节数组

```
{ }  rhythm_axe:maps.<mapid>：谱面根标签。
├── id: "new_beginning"                        [字符串]  谱面标识符，同时也是计分板前缀。
├── title: "{\"text\":\"新手教程\"}"            [文本组件] 谱面显示标题（1.21.5+ 以 NBT 存储；编辑器对话框可输入**纯文本**（如 新手教程，支持空格），
│                                                         也可输入 JSON 文本组件：带引号字符串 "新手教程"/对象 {"text":"标题"}/列表[{},{}]，存为字符串；
│                                                         也可直接存复合/列表 NBT（如逐字渐变标题）。显示处用 utilization/title_comp 生成标题组件：
│                                                         JSON 组件字符串直接宏传；裸纯文本合成字面组件；复合/列表 NBT 走 {"nbt":..,"interpret":true} 由游戏解析。）。
├── artist: "作者名"                            [字符串]  谱面作者（编辑器界面显示"歌曲名 - 作者"）。
├── music: "music/rhythm/new_beginning"        [字符串]  音乐文件路径（供 playsound 使用）。
├── preview: "music/rhythm/new_beginning_pre"  [字符串]  预览音频路径（供 playsound 使用）。
├── teleport: 1b                               [Bool]    是否在开始游戏时将玩家传送至初始位置。
├── spawn_x: 0.0d                              [Double]  玩家初始位置 X（tp 目标坐标）。
├── spawn_y: 0.0d                              [Double]  玩家初始位置 Y。
├── spawn_z: 0.0d                              [Double]  玩家初始位置 Z。
├── spawn_yaw: 0.0d                            [Double]  玩家初始朝向（偏航，度）。
├── spawn_pitch: 0.0d                          [Double]  玩家初始朝向（俯仰，度）。
├── player_count: 1                            [Int]     最大支持同时游玩人数，默认 1（单人）。
├── health: 10                                 [Int]     初始及最大生命值，可被事件修改。
├── highest_score: 0                           [Int]     历史最高分（运行期结算写入，谱师不编写；每谱面独立、持久化）。
├── end_time: 5760                             [Int]     谱面结束点（刻数），播放到此时执行结束流程。可选，未定义时时间轴进度条显示为红色混凝土。
├── editor_playhead: -1                        [Int]     编辑器上次保存时播放头所在位置（刻数）；打开编辑器时恢复到该位置。可选，旧谱面无此字段时编辑器从开头（seek_start）开始。
├── [ ]  notes：音符列表，按 time 升序排列。每个音符含稳定的 `id`（见下）。
│   └── { }  一个音符。字段按需存储，省略的字段使用下表默认值。
│       └── 音符共通标签[下方链接]
├── [ ]  timing_points：时间点列表，按 time 升序排列。**首个元素的 time 必须为 0**。
│   └── { }  单个时间点（红线/绿线）。**第一条（time=0）恒为红线**；后续时间点：BPM 相对上一条发生变化→红线，BPM 相同→绿线。
│       ├── time: 0                            [Int]     起始时间，单位刻。
│       ├── bpm: 175.0f                        [Float]   拍每分钟。播放器据此执行 `tick rate <bpm>bpm <tpb>`。
│       ├── bpb: 4                             [Int]     每小节拍数（beats per bar）。
│       ├── tpb: 8                             [Int]     每拍刻数（ticks per beat）。
│       └── judgement_scale: 1                 [Int]     判定区间缩放倍数，>=1，默认 1。
└── [ ]  events：事件列表，按 time 升序排列。
    └── { }  单个事件。
        ├── time: 512                          [Int]     执行时间，单位刻。
        └── commands: [...]                    [List]    指令列表，到时间后按顺序逐条用宏执行。
            └── "playsound ..."                [字符串]  一条命令字符串。
```

[音符共通标签](音符.md#音符nbt结构)

> **音符寻址**：游戏内生成实体时打 tag `{mapid}_n{id}`（id 为音符的稳定唯一 id，如 `new_beginning_n42`），播放器通过 tag 精确选择实体。

### 存储示例

向已有谱面追加数据时使用 `data modify ... append`：

```mcfunction
# 追加一个音符
data modify storage rhythm_axe:maps.new_beginning notes append value { \
    id: 42, \
    type: 3, \
    time: 256, \
    duration: 32, \
    color: 5, \
    density: 8, \
    size: 1.5, \
    position: [1.0d, 0.0d, -0.5d], \
    start_pos: [-3.0d, 0.0d, 0.0d], \
    note_base_life: 32, \
    anim_easing: 1, \
    anim_power: 1, \
    hitsound: 1, \
    hit_particles: 1, \
    hit_events: [ \
        { \
            command: "function xxx", \
            enabled: { \
                spawn: 0b, \
                bad: 0b, \
                good_early: 1b, \
                perfect_early: 1b, \
                perfect: 1b, \
                perfect_late: 1b, \
                good_late: 1b, \
                miss: 0b, \
                damage: 0b \
            } \
        } \
    ], \
    custom_tag: "" \
}

# 追加一个时间点（BPM 变化）
data modify storage rhythm_axe:maps.new_beginning timing_points append value {
    time: 512, bpm: 200.0, bpb: 4, tpb: 8
}

# 追加一个事件（两条指令，按顺序执行）
data modify storage rhythm_axe:maps.new_beginning events append value {
    time: 1024,
    commands: [
        "playsound minecraft:block.note_block.pling master @a ~ ~ ~ 1 1",
        "effect give @a speed 5 1"
    ]
}
```

> **默认值约定**：存储时只保留被修改过的字段，未出现的字段使用上表中的默认值。

### 时间点字段速查

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `time` | Int | ✅ | — | 起始时间（刻数）。首个时间点必须 time=0 |
| `bpm` | Float | ✅ | — | 拍每分钟，计算方法：`tick rate <bpm>bpm <tpb>` |
| `bpb` | Int | ✅ | — | 每小节拍数（beats per bar） |
| `tpb` | Int | ✅ | — | 每拍刻数（ticks per beat） |
| `judgement_scale` | Int | ❌ | 1 | 判定区间缩放倍数，>=1，见[音符→属性→判定区间缩放倍数](音符.md#判定区间缩放倍数) |

> **一刻内只能有一个时间点或事件点**：同一刻（相同 `time`）至多允许 1 个时间点、1 个事件点；时间点与事件点可共存（如 `time=512` 既可有一个时间点又可有一个事件点），但不能在同一刻出现 2 个时间点或 2 个事件点。

**R/G 时间点**：

- **R（红线）**：bpm 或最终 tps 发生变化的时间点，到达时播放器执行 `tick rate $(bpm)bpm $(tpb)`，同时改变轨道染色规则，并认定为新的小节
- **G（绿线）**：bpm 和 tps 均不变，仅改变轨道染色规则（每小节刻数/每拍刻数变化），不影响 tick rate

> 最终 tps = bpm × tpb ÷ 60（判定是否变化时用 ×1000 整数比较 `bpm×tpb×1000`，避免浮点误差）

### 事件字段速查

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `time` | Int | ✅ | — | 执行时间（刻数） |
| `commands` | List | ✅ | — | 命令字符串列表，支持 function/playsound/tellraw 等；到时间按顺序逐条执行 |

**执行方式**：播放器到时间后对该事件的 `commands` 逐条用**宏**执行——`$execute positioned 0.0 0.0 0.0 run $(command)`。谱师在编辑器聊天栏中直接输入命令字符串保存，无需创建 .mcfunction 文件。

> **一刻内只能有一个时间点或事件点**：同一刻（相同 `time`）至多 1 个事件点，且与至多 1 个时间点可共存，但同一刻不能出现 2 个事件点。

主要用途：effect、fill 等特效指令，以及其他自定义逻辑。
