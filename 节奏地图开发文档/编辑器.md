# 编辑器

## 介绍

- 用一个function命令作为入口打开编辑器并且指定一个作为要修改的谱面。
- 编辑器会读取谱面的内容，在编辑区域生成时间轴和音符、事件，让谱面内容可视化、可编辑化。
- 在游戏世界里根据当前谱面内容，完整重现谱面游玩时的状态
- 与游玩模式一样会用bossbar显示当前播放进度
- 使用[**伴侣mod**](工具组件.md#工具组件)让谱面的内容更加易于编辑，主要包括音频的播放控件系统
- 定义所有操作，使所有操作可逆
- 错误检测系统，对谱面的问题操作进行警告和报错（自动谱面格式校验规划中，暂未实现）

> 当一个玩家处于谱面编辑状态，那么它将不被允许开始游戏，聊天栏提示将要和他一起开始游戏的所有玩家“{player}正处于谱面编辑状态，无法开始游戏”
> 当进入编辑器，玩家会根据谱面的传送开关与否来决定是否传送到谱面位置
> 当重进存档（每次运行load）
>
> - 如果编辑器仍处于打开状态：【编辑器】 编辑器未关闭
> - 如果不仅处于打开状态而且还有没保存的内容：【编辑器】 编辑器未关闭且有未保存的内容
>

## 数据结构与状态

编辑器的运行时状态统一存放在 `rhythm_axe:maps.editor`，当前编辑的谱面 id 存在 `mapid` 键。

- **单人锁**：编辑器同一时间只允许一个玩家使用——玩家进入编辑器时打上 `editor_active` 标签并记录其 UUID；其他玩家尝试打开编辑器时提示"编辑器已被占用"；已在编辑的玩家再次尝试打开时提示"您已经进入编辑状态了"；退出编辑器时移除标签并清理状态。

```plain
rhythm_axe:maps.editor
├── mapid: "new_beginning"        [字符串]  当前编辑的谱面 id
├── active: 1b                    [Bool]    是否有玩家在编辑
├── player: "<玩家UUID>"           [字符串]  正在编辑的玩家
├── history[]                     [列表]    历史快照（完整谱面快照，见下）
├── history_cursor: 3             [Int]     当前快照指针
├── saved_cursor: 2               [Int]     最近一次保存的快照指针（未保存判定 = history_cursor != saved_cursor）；可为 -1 表示保存基线已被截断丢弃（无保存基线，未保存计数恒 >0）
├── clipboard[]                   [列表]    剪贴板（{note_ids:[...], notes:[...]}，多选音符）
├── selection[]                   [列表]    选中集（音符 id）
├── playhead: 128                 [Int]     播放头当前时间（刻）
├── next_note_id: 43              [Int]     下一个新建音符的 id（新建后自增）
├── playing: 0b                   [Bool]    是否播放中
├── play_speed: 1.0f              [Float]   播放速度倍率（0.25/0.5/0.75/1.0）
├── metronome: 0b                 [Bool]    节拍器开关
├── tool_group: "note"            [字符串]  当前工具组
├── tool_page: 0                  [Int]     工具组翻页
├── editing: {}                   [复合]    当前打开的面板状态（时间点/事件面板与查找共用）
│   ├── ref: 5                    [Int]     引用：时间点/事件用数组索引（新增模式无此键）
│   ├── original: {}              [复合]    进入编辑时的原值（【取消】时恢复；暂未使用）
│   ├── temp: {}                  [复合]    面板暂存副本（时间点字段 / 事件 time+commands；编辑改 temp，【确认】才写回并进历史）
│   ├── is_new: 1b                [Bool]    新增模式（键存在 = 新增面板）
│   ├── delete_armed: 1b          [Bool]    删除二次确认武装状态（时间点/事件面板）
│   ├── cmd_target: 0             [Int]     事件面板：对话框编辑/删除的目标指令序号
│   ├── find_is_event: 1b         [Bool]    查找类型标记（事件；缺省=时间点）
│   └── find_is_note: 1b          [Bool]    查找类型标记（音符）
├── delete_confirm: {}            [复合]    删除二次确认状态
│   ├── type: "note"              [字符串]  目标类型
│   ├── ref: 5                    [Int]     引用：音符用音符 id，时间点/事件用数组索引
│   └── time_left: 100            [Int]     确认倒计时（刻）
├── panel_temp: {}               [复合]    谱面设置面板的暂存副本（只含面板编辑的根字段；【保存设置】时才写回并进历史）
├── events_page: 0               [Int]     事件列表当前页（每页 editor_event_per_page 个，默认 5）
└── input: {}                     [复合]    对话框输入状态（当前输入目标字段，见"字符串输入"）
```

> 播放头、节拍器、显示长度、历史游标等需要逐刻运算的数值镜像到 `editor` 计分板（见下表）；`play_speed` 为浮点，仅在 storage 保存。

### 编辑工作副本与撤销/重做

编辑期间（包括新建谱面），谱面数据**不直接写入** `rhythm_axe:maps.<mapid>`。每次操作（放置音符、修改属性等）会将当前完整谱面数据复制一份**快照**，存入历史记录数组 `rhythm_axe:maps.editor.history[]`。另有一个指针 `history_cursor` 记录当前位于哪一份快照。**只有执行保存操作才会把工作副本写入 `rhythm_axe:maps.<mapid>`**。

```plain
rhythm_axe:maps.editor.history[]
├── [0]  打开编辑器时的初始状态（已有谱面从正式存储加载；新建谱面为默认模板）
├── [1]  第 1 次操作后的状态
├── [2]  第 2 次操作后的状态
├── [3]  第 3 次操作后的状态  ← history_cursor = 3（当前）
├── [4]  （新操作会 push 到这里，cursor 移到 4）
└── ...
```

- **每次操作**：将当前谱面数据 `append` 到 `history[]` 末尾，`history_cursor += 1`
- **撤销**：`history_cursor -= 1`，将谱面回滚到 `history[history_cursor]`
- **重做**：`history_cursor += 1`，将谱面恢复到 `history[history_cursor]`
- **执行新操作**（在撤销后）：清空 `history[history_cursor+1]` 之后的所有快照，然后追加新快照——撤销后走岔路，旧分支被丢弃
- **保存**：备份 `highest_score` → 逐键清空 `rhythm_axe:maps.<mapid>` 根字段 → merge 当前快照 → 写回 `highest_score`（防字段残留）；并把 `saved_cursor` 设为 `history_cursor`；**不修改历史记录**（保存后仍可撤销回到更早状态）
- **退出**：清空 `history[]`（无论是否保存）；退出前按 `history_cursor != saved_cursor` 判断是否有未保存内容：
  - 如果有未保存内容：
    - 【保存并退出】：执行保存后退出
    - 【不保存并退出】：直接清空 `history[]`，原谱面数据不受影响
  - 如果没有未保存内容：
    - 直接退出，不弹出提示

这样在保存前原始谱面数据始终不受损，同时为多级撤销/重做提供了实现基础。历史记录数量上限为全局设置 `editor_history_limit`（默认 50），超出时丢弃最旧的快照（移除 `history[0]`，`history_cursor` 相应 -1）。由于 `saved_cursor` 保存的是 history 的**绝对下标**，裁剪、截断都必须同步维护它，否则未保存判定/计数会失真：
- **裁剪（trim，超出上限丢最旧）**：`history_cursor` 与 `saved_cursor`（若 >0）都 -1；
- **截断（truncate，撤销后开新分支丢 redo 尾部）**：若已保存的快照位于被丢弃的 redo 分支（`saved_cursor > history_cursor`），则设 `saved_cursor = -1`（无保存基线，未保存计数恒 >0），待下一次保存恢复为正常下标。

### 剪切板

各面板的复制/粘贴使用**各自独立的剪贴板键**（互不覆盖），生命周期为**面板会话内**——打开对应面板/列表时清空，复制内容只在本次会话内有效，离开面板再进入即失效；退出编辑器时随 `clear_state` 一并清空。

| 剪贴板键 | 用途 | 复制来源 | 粘贴去向 | 清空时机 |
| --- | --- | --- | --- | --- |
| `maps.editor.timing_clip` | 时间点（行级） | 时间点列表【复制】/ 时间点面板【复制】 | 时间点列表【粘贴】/ 时间点面板【粘贴】 | 打开时间点列表时清空 |
| `maps.editor.event_clip` | 事件点（行级） | 事件列表【复制】/ 事件面板【复制】 | 事件列表【粘贴】/ 事件面板【粘贴】 | 打开事件列表时清空 |
| `maps.editor.note_clip` | 音符（行级） | 音符列表【复制】 | 音符列表【粘贴】（覆盖该行） | **从面板外**进入音符列表时清空（列表内刷新/翻页保留） |
| `maps.editor.editing.he_clipboard` | 音符击打事件（行级） | 击打事件面板【复制】 | 击打事件面板【粘贴】（覆盖该行） | 打开/取消/确认击打事件面板时清空 |
| `maps.editor.clipboard` | 多选音符（全局操作剪贴板，`{note_ids:[...], notes:[...]}`） | `note/copy`、`note/cut` | `note/paste`（新建音符） | 退出编辑器时清空（`clear_state`） |

> `clipboard` 是多选/剪切的**全局操作剪贴板**（与具体面板无关，供选择工具批量复制/剪切/粘贴）；其余四个为**面板级行剪贴板**，各自独立、打开对应面板即清空。
>
> **`note_clip` 清空时机已放宽（2026-09-17）**：只有**从面板外进入**音符列表才清空（判定 = 进入前 `current_panel` 不是 10）；列表内的**任何原地刷新**都保留剪贴板 —— 翻页、勾选、全部选中、取消选中、翻转/镜像开关、批量操作收尾，以及暂停继续·调速·跳转触发的 `menu/resume` 重绘。否则「复制一个音符 → 顺手翻页/暂停 → 剪贴板被清、【粘贴】莫名变红」。离开列表（回主菜单、进面板 11 等）后 `current_panel` 不再为 10，再次进入即失效；退出编辑器时仍由 `clear_state` 统一清空。

### 各类操作的入口 function

编辑器底层操作全部做成**入口 function**（界面层只负责调用，前置参数写入 `rhythm_axe:prop`，键用后即删）。除剪贴板复制与跳转外，所有修改类操作内部自动完成 `file/begin`（截断撤销后的分支）→ 修改 `history[cursor]` → `file/commit`（追加快照 + 超上限裁剪），一次操作 = 一份快照。

- **文件类**（宏参数内联传入）：
  - `editor/file/delete {mapid:"xx"}` —— 删除谱面：移入 `rhythm_axe:maps.trash.<mapid>`（同名覆盖）后删正式存储；谱面不存在/正在编辑中会拒绝并提示
  - `editor/map/modify` —— 前置 `prop.map_fields`（只 merge 传入的根字段：title/artist/music/preview/teleport/player_count/health/end_time/spawn_x/spawn_y/spawn_z/spawn_yaw/spawn_pitch）
- **音符**（prop 前置，note/ 下按操作前缀分子目录）：
  - `editor/note/create/create` —— 前置 `time`（判定时间刻）+ `type`（0-4）；可选字段见 prop 键表。按 time 升序插入，id 从 `next_note_id` 分配并自增
  - `editor/note/delete/delete` —— 前置 `note_id`；未找到不产生快照
  - `editor/note/copy/copy` —— 前置 `note_ids`（音符 id 列表，缺省用 `maps.editor.selection`）；整音符快照收集到剪贴板 `{note_ids:[...], notes:[...]}`，提示“已复制 x 个音符”（不产生快照）
  - `editor/note/cut/cut` —— 同 copy，收集后删除原音符（一次快照），提示“已剪切 x 个音符”
  - `editor/note/paste/paste` —— 可选 `time`（粘贴基准：剪贴板中最小 time 的音符放到 time，其余保持相对偏移；不传则保持原 time）；逐个重新分配 id 并按 time 升序插入，提示“已粘贴 x 个音符”
  - `editor/note/modify/modify` —— 前置 `note_id` + `note_fields`（只 merge 传入字段，不含 time；未找到不产生快照）
  - `editor/note/retime/retime` —— 前置 `note_id` + `time`（新判定时间）；摘出音符改时间后按 time 升序重新插入（id 不变，保持升序）
- **时间点**（prop 前置）：
  - `editor/timing/create` —— 前置 `time`+`bpm`+`bpb`+`tpb`，可选 `offset`/`judgement_scale`；按 time 升序插入
  - `editor/timing/modify` —— 前置 `index` + `timing_fields`（只 merge 传入字段）
  - `editor/timing/delete` —— 前置 `index`；首个时间点（index 0）不可删除
  - `editor/timing/prev` / `editor/timing/next` —— 播放头跳到上/下一个时间点（播放中自动重同步音乐与 tick rate）
- **事件点**（prop 前置）：
  - `editor/event/create` —— 前置 `time`，可选 `commands`（指令列表）；按 time 升序插入
  - `editor/event/modify` —— 前置 `index` + `event_fields`（只 merge 传入字段，如 `commands`）
  - `editor/event/delete` —— 前置 `index`
  - `editor/event/prev` / `editor/event/next` —— 播放头跳到上/下一个事件点

调用示例（游戏内）：

```mcfunction
# 在 512 刻创建音符盒（位置取玩家脚下，其余默认）
data modify storage rhythm_axe:prop time set value 512
data modify storage rhythm_axe:prop type set value 0b
function rhythm_axe:editor/note/create/create

# 删除音符 3
data modify storage rhythm_axe:prop note_id set value 3
function rhythm_axe:editor/note/delete/delete

# 在 512 刻追加时间点（BPM 200、每小节 4 拍、每拍 8 刻）
data modify storage rhythm_axe:prop time set value 512
data modify storage rhythm_axe:prop bpm set value 200.0f
data modify storage rhythm_axe:prop bpb set value 4
data modify storage rhythm_axe:prop tpb set value 8
function rhythm_axe:editor/timing/create
```

5. 出生顺序与「补扫出生」（2026-09-21 修）

    **问题**：`notes` 按 `time` 升序，但**出生刻 `birth = time − note_base_life×16/流速` 在 `base_life` 不统一时不单调**
    （例：`base_life=12` 的玻璃排在 `base_life=32` 的唱片机前面 → 后者反而出生更早）。
    播放时只靠「队首未出生就停」的出生游标（`#vis_next` / `tick_birth_*`）⇒ 排在后面、前导更长的音符会被压到挡路音符出生后才生成。

| 现象 | 原因 |
| --- | --- |
| 音符只剩后半程才出现、一出现就已经走过一半 | 生成时刻被压到「挡路音符的出生刻」，此时它的进度早已不是 0 |
| 快进/快退「逐刻看没问题」 | 它们走 `refresh` 全表重建，不看 `birth` 顺序 |

    实测 `lament_rain`：1424 音符中 **61 个**被延迟 1~24 刻（如 `id=1889`：出生 3052 被 `id=1888`（出生 3069）挡住 → 判定前 15 刻才出现、进度 53%）。

    **修法**（新增 `visual/scan_due` + `_drive` + `_leaf`）：每刻在游标之后**补扫**一遍「本刻恰好出生」的音符。

| 时机 | 动作 |
| --- | --- |
| 队首音符出生当刻 | 游标走法生成（`tick_birth_*` 认 `playhead == birth`）并推进 |
| 队首之后、本刻恰好出生 | 补扫生成（`scan_due` 认 `birth == playhead`，复用 `spawn_one_`） |
| 已过出生刻 | 只推进游标，**不重复生成**（该音符已由补扫 / seek 的 `refresh` 生成过） |

    - 两条路都只认 `birth == playhead` **精确一刻** ⇒ 每个音符只生成一次；若沿用旧的 `playhead >= birth` 会把补扫已生成的音符**重复召唤**（重置判定状态）。
    - 扫描窗口上界 = **全谱最大前导** `vis_lead_max`（`refresh` 遍历时由 `spawn_one_` 统计、落盘 `rhythm_axe:editor.runtime`）：`time − playhead > 上界` 之后不可能有本刻出生者 ⇒ 实测平均只多看 ~11 个音符/刻。
    - 依赖的不变量：`#vis_next` 永远停在「第一个出生刻 ≥ 播放头」的音符上（由 `spawn_one_` 记录），所以补扫覆盖「游标之后」即等于覆盖「全部还没生成的」。

### 真实判定模式

> 开关：**主菜单行 105 的【游玩测试：开/关】（`10502`）**，与节拍器（`10501`）同行。值 = `options.editor_note_judge`（默认 **1 开**）。
> 目的：让谱师在编辑器里**照着真实游玩的手感试打**——有判定、有反馈，但**不计成绩与连击**。

| 开关 | 试听行为 |
| --- | --- |
| **开**（默认） | 音符在判定窗内等输入：命中 → 按等级播音符事件；超窗 → miss（木板静默清除） |
| **关** | 旧行为：不判定，到判定时刻按 `perfect` 直接播音符事件（等同 auto） |

**判定输入（照搬游玩语义）**

| 类型 | 输入 | 判定窗 |
| --- | --- | --- |
| 0 音符盒 | **看向**（视线命中，与游玩 `judgement` 同一 `predicate rhythm_axe:looking_at`） | `[3x, -2x]`，命中按当前寿命查档 |
| 1 木板 | **看向**（同 `main_plank`） | **`[2x, -2x]`**（无 bad 段：`[2x+1,3x]` 内看着也不判），命中**恒大 P** |
| 2 唱片机 | **左/右键点击**音符 | `[3x, -2x]` 按点击时刻寿命查档；**life == -2x 仍未点击 → 看向则 good_late，不看则 miss**（照搬 `jukebox_late`） |
| 3 混凝土 | **站位判定**（照搬 `main_concrete`）：段内任意刻玩家在判定区域 → 该段大P；段末不在区域 → 该段 miss；含保护1/2（首段过早离开 / 末段过短延长 3x） | — |
| 4 染色玻璃 | 碰撞扣血的**反馈部分**（不扣血、不计成绩）—— ⏳ 待搬（需前后帧中心点做扫掠） | — |

**窗口与等级**：与游玩**同一套边界**（x = 当前时间点的 `judgement_scale`）

| life = `editor_n_time − playhead` | 等级 |
| --- | --- |
| `[2x+1, 3x]` | bad |
| `[x+1, 2x]` / `[1, x]` | good_early / perfect_early |
| `0` | perfect |
| `[-x, -1]` / `[-2x, -x-1]` | perfect_late / good_late |
| `< -2x` | miss |

- **木板特例**（照搬游玩 `main_plank`）：命中**恒大 P**（无 bad 段）；未抵达判定位置（`life ≥ 1`）被注视**只记录、不当场判**，抵达判定位置及之后（`life ≤ 0`）有记录或此刻被注视才判；超窗**静默清除**（无 miss 反馈）
- **判定保护**（照搬游玩 `protected`）—— **只有音符盒**（木板天然是「先记录、后结算」，不需要保护状态）：
  - **进入**（只置状态，**不判定**）：`life == 3x+1` 且本刻**视线经过判定位置**（完美判定区域；靠射线步进 `editor/judge/raycast` 判定）
  - **记录**（保护期 `[3x,0]`，**暂不判定**）：「看着」= 视线与**音符**相交 **或** 视线在**完美判定区域**内（判定位置，`judge/raycast` 打标）→ 记录当刻寿命；结算时的「看着」同口径。
    > 后者对应文档情况 2-A「直到取得大P准星一直在完美判定区域 ⇒ 大P」：`life>0` 时音符还在飞行、不在判定位置，**只认“命中音符”会让这种打法一条记录都没有**（还会因 `tick_one` 先判定后 `place` 而更难命中）→ 全程盯着判定位置反而拿 PL。
  - **结算**（`life == 0`）：有记录且当前看着 → 大P；有记录没看着 → 按记录寿命；无记录但看着 → 大P
  - ⚠ **进入保护 ≠ 保证大P**：保护期内从未与**音符**相交 ⇒ 无记录 ⇒ **等同无保护**（退回“相交那一刻的寿命”判：`life < 0` 时看音符仍可拿 perfectL / goodL）；始终不相交才由出窗收尾（miss）
  - **判定位置的代表**：编辑器**展示实体 `Pos` 恒 = 判定位置**（视觉位置在 `transformation.translation` 上）⇒ 和游玩一样可直接拿展示实体做射线步进，不需要额外 marker
- **木板的「被注视」**（`note_check` 分支 B，★ 2026-09-26）：视线与**音符**相交 **或** 视线在**完美判定区域**内 —— 后者同样兜住 `tick_one` 先判定后 `place` 的时序（两处口径一致）

- **混凝土（type 3）**：`judge/concrete_check`，逐刻按寿命现算「待判段 p = 已判段数+1」（`editor_n_c_last`），**每刻最多推进一段** ⇒ 天然抵抗快进/拖进度条跳段；
  判定区域用展示实体自身（`Pos` = 判定位置、`Rotation.yaw` = 运动方向，检测前 `rotated ~ 0` 归零 pitch）；
  漏判兜底：寿命低于本段下界时每刻静默推进一段（不补播反馈）；出窗上界在游玩测试模式下延到 `time+dur+3x+1`（覆盖末段过短延长）。
  - **seek 的取舍**（2026-09-21）：重建（快进/快退/刷新）时 **段进度 `editor_n_c_last` 会按播放头预置**（= 播放头之前的段视为已判过，`fill_disp` 里算），所以不会出现"一播放就从第 1 段连续补判"；
    但 **保护1 的记录 `editor_n_rec_life` 不预置**（归 −1 无记录）——记录窗口只有判定的前 `1~3x` 刻，播放头越过它之后就再没机会记录 ⇒ 此时段末不在区域内按 **miss** 收尾，而非按"提前就位"判级。
    这是有意为之：seek 之后"当时到底站没站"已无从得知，不编造记录；重建后只要在段末站进区域，照样判大 Perfect。

- **同一刻判定限制**（规则表见 `音符.md`；游玩与编辑器试玩一致）：
  - 判定前先由 `editor/judge/probe` 预扫全部存活普通音符，**只放行 `note_life` 最小（= time 最小、最靠前）的那一批**候选（`time` 相同的整批放行）
  - 候选 = 本刻命中（视线 / 点击）+ 寿命在判定窗内 + 未判定 + 非保护中 + type 0..2；**被压制的候选本刻不判、不惩罚**（下刻寿命 −1 后重新参与，若因此越过窗口则照常 miss）
  - 链路：`visual/tick` 每刻置 `#ed_min_life = 999999` → `as @e[tag=editor_note] at @s run judge/probe`（顺带把命中标记写进各实体的 `editor_n_hit`）→ 再 `tick_one` → `judge/note_check` 只判 `life == #ed_min_life`
  - **必须两遍**：判定不许依赖逐音符的遍历顺序；命中检测只在 probe 里做一次，`note_check` / `protect` 直接读 `editor_n_hit`
  - **保护中音符不算候选、不占名额**，其 `life == 0` 的结算不受此限制（结算时刻固定，推迟就破坏保护语义）
  - 与游玩的差异：游玩的 `looked_at_perfect` 打在交互实体上（再按 note_id 配对回音符）；编辑器**直接打在展示实体上**（判定主体就是它），省掉配对查找
  - 实现：`editor/judge/raycast`（入口）+ `raycast_init` + `raycast_step`（每 0.5 格采样、`distance=..1.0`），由 `visual/tick` 每刻**先清后打**，保证同刻的保护进入检查读到本刻结果

### 引导线

连接相邻 0/1/2 音符的青色玻璃条（`item_display` + `cyan_stained_glass`），提示音符间位置关系。设：

- A = 前一个开启引导线的 0/1/2 音符，**引导线由 A 拥有/生成**，指向它的**紧邻下一个音符** B（B 是否开启不影响）
- n = B 判定时刻 − A 判定时刻；m = 播放头 − A 判定时刻
- l =
  - `m<0`（A 未抵达判定位置）：A、B **视觉中心**的距离
  - `0≤m<n`（A 已抵达判定位置）：B 的视觉中心 到 A 判定位置的距离

**触发条件**：每个 `following_point=true`（开启引导线）的 0/1/2 音符 A 都会生成一条连向它**之后的下一个 0/1/2 音符 B** 的引导线（B 是否开启 `following_point` 不影响）；**混凝土/玻璃（3/4）不生成引导线且会被跳过**（A 连向其后第一个普通音符）；未开启的音符 A 不生成（即使它的下一个 B 开启，A 与 B 之间也不连）。预扫描为每个开启音符记录其下一个普通音符 `guide_prev.notes[].next_*`。

**生命周期**（引导线实体在每次重建/refresh 时即生成，A 未出生时 `scale.z=0` 隐藏）：

1. **A 出生 → B 出生**：A 出生时引导线显示。A 端用 A 的实时视觉中心（`editor_n_vx`），B 端连 **B 的出生点**（=判定位置+起始位置，存为 `note_guide_sx/sy/sz`）。
2. **B 出生 → B 判定**：A、B 都在，两端都用实时视觉中心。
3. **A 已判定**（`0≤m<n`）：A 端用 A 的判定位置快照（`note_guide_x/y/z`），长度按 `L = l×(n−m)/n` 收缩，**B 端锚定**；`m≥n` 时引导线消失。

**端点/长度**：A、B 端点取 `place` 计算的音符视觉中心（`editor_n_vx/vy/vz`，×1000→/10→×100）；B 未出生时用 `note_guide_sx/sy/sz`（出生点 = 判定位置+起始位置，×100）。长度 = 端点距离 × 收缩因子（`s = (n−m)/n`，×1000 定点，`m<0` 全长）。

**实体 `Pos` 锚点（2026-09-21）**：

| 项 | 值 |
|---|---|
| 实体 `Pos` | **A 端判定位置**（生成时 `summon` 在 A 的判定位置，随即由 `utilization/guide_anchor_set` 读回真实 `Pos` 存 `note_guide_px/py/pz` ×100） |
| `transformation.translation` | 「世界中点 − 锚点」（每刻 tick 写入，见 tick_body） |
| 初始状态 | `scale.z=0`（不可见），首刻由 `guide_tick` 写入真实几何 |

> **为什么不能用世界原点**：展示实体只有落在**玩家附近**（客户端追踪范围内）才会收到更新，**区块强加载并不能让它更新** —— 原先把世界坐标全塞进 `translation`、`Pos` 留在原点的做法，谱面一旦远离原点就会表现为引导线不跟随/看不见。顺带也躲开了「往未加载区块 summon 后选择器找不到实体」的隐患。

> **说明 / 修复记录**
> - `following_point` 默认 `false`（`build_`/`create`/`note_panel_open_`），需在音符面板勾选才开启；面板显示与切换按**值**判断（`if data` 存在性判断会误把 `0b` 当启用）。
> - 端点不用 `Pos + transformation.translation`（该值曾被证实与音符视觉中心符号相反），而是用 `editor_n_vx`。
> - 3D 距离曾把 `dz²` 重复累加（`√(dx²+dy²+2dz²)`），已改为 `√(dx²+dy²+dz²)`。
> - 收缩因子 `s` 曾在 `n−m<n` 时因整数除法塌成 0（第二阶段引导线消失），已用 ×1000 定点修复。
> - 引导线**归属 A**（`note_guide_a=A`、`note_guide_b=B`），由 A 的 `spawn_skip_`/`guide_build_for_` 生成；B 端未出生时连 **B 出生点**（=判定位置+起始位置，`note_guide_sx/sy/sz`），B 出生后切实时。
> - 引导线"出生"以**音符 A 是否存在**为准（`guide_tick` 里 `#a_born` 检查），A 未出生时设 `scale.z=0` 隐藏。
> - 引导线实体 `Pos` 曾是恒定 `(0,0,0)`、世界坐标全在 `translation` 里（2026-09-21 修正为「锚在 A 端判定位置 + `translation` 存相对偏移」，原因见上）；`guide_spawn_` 里那段「兜底初始位置」的 B 端取的是 `prop.pos_x`（= A 自己的判定位置）⇒ 中点恒 = A、长度恒 = 0、又配 `scale.z=0`，属死代码，已删。

**新建/打开**：使用命令 `function rhythm_axe:editor/editor` 并传入谱面 id：

- 若 `rhythm_axe:maps.<mapid>` **已存在** → 直接加载其内容进入编辑模式
- 若**不存在** → 以默认模板建立**编辑工作副本**（仅写入 `rhythm_axe:maps.editor.history`，**不创建** `rhythm_axe:maps.<mapid>`）：

    3. 自动追加 `time=0` 的初始时间点（默认 150 BPM、4/4 拍、8 tpb）
    4. `spawn_x/spawn_y/spawn_z` 默认为玩家当前位置，`spawn_yaw/spawn_pitch` 默认 0
    5. 打开编辑器界面

**编辑状态下再次执行 editor 命令**（切换谱面）：

- 目标 mapid **与当前编辑谱面相同** → 提示“您已经在编辑这张谱面了【返回编辑器】”，不切换
- 目标 mapid **不同** → 弹出**切换谱面确认**面板（`current_panel` 15），显示“您当前正在编辑 {标题}-{作者}（mapid:{mapid}）”，按是否有未保存内容给按钮：
  - **有未保存内容**：`【保存当前谱面并开始编辑新谱面】`（911，先保存再切换）/ `【丢弃当前谱面改动并且开始编辑新谱面】`（912，不保存直接切换）/ `【继续编辑当前谱面】`（903）
  - **无未保存内容**：`【编辑新谱面】`（913，直接切换）/ `【继续编辑当前谱面】`（903）
- 待切换目标存于 `maps.editor.pending_mapid`；切换 = 清空当前编辑状态（`init_state`）后重新 `open`
- 【继续编辑当前谱面】= 903（consume 开头的恢复逻辑），回到进入切换确认前的面板（面板 15 恢复时回主菜单）

> 只有执行**保存**操作才会把工作副本写入 `rhythm_axe:maps.<mapid>`；新建的谱面退出前不会自动保存，需手动执行保存操作。

**修改谱面id**：以新 id 创建新谱面 → 复制原谱面的全部内容 → 重建计分板（删除旧前缀计分板、创建新前缀计分板，计分板前缀 = 谱面id）→ 删除原谱面 storage（`rhythm_axe:maps.<旧id>`）。历史记录不受影响。

**保存**：把editor内容写入mapid

**退出**：

- 没有未保存内容：直接退出，清空状态
- 有未保存内容：退出之前提示是否要保存内容

**导入音频**：往材质包里添加音频，并且在`sounds.json`里定义

> - 如果你通过进行这个操作改写音符的位置，但是同时在音符属性控制面板上也改写了音符的其他位置，那么最终还是会把面板上的内容写入音符

批量编辑：

- 如果有音符在时间相对平移之后的判定时间<0，则那个音符只平移到0，并且所有音符平移的数值一样。比如第一个音符在第10刻，往前平移20刻，那么因为最多只能往前平移10刻所以效果相当于所有音符往前平移10刻

### trigger值

#### 触发链（三层结构）

```
点击编辑器按钮 → /trigger editor_click set <值>
  → tick 检测 @a[scores={editor_click=1..}] → function rhythm_axe:editor/menu/consume
      ├─ 读值 → reset → enable，并播放 UI 点击音
      ├─ 【第一层】全局值（任意面板可用，处理完 return）
      │    903 恢复编辑 / 8 撤销 / 9 重做 / 20..29 时间控件
      ├─ 未 active → return fail
      ├─ 会话自检 session_mapid_fix（补 editor.mapid，防宏参数缺失静默失败）
      ├─ 【第二层】按 #panel_id = current_panel 分流
      │    execute if score #panel_id editor matches <N> run return run function .../panel/panelN
      │      └─ panelN：先跑白名单守卫（不属于本面板 → wrong_panel + return fail），再按值分发
      └─ 兜底 function .../wrong_panel
```

#### 编号规范（spec v2）

**核心：值 = 行号 × 100 + 列码。** 行号 = 按钮位于面板第几行（≥100，避免与早期小值冲突）；列码 = 该行第几个按钮（从 1 起）。

| 场景 | 公式 | 示例 |
| --- | --- | --- |
| 固定控件（行号 ≥ 100） | `行号×100 + 列码` | `12001` = 行 120 第 1 个按钮 |
| 动态行（每页 ≤9 行，如事件指令） | `(1000+页内行序)×100 + 列码` | `10757` = 行 1007 列码 7 |
| 动态行（每页 40 行，如音符列表） | `100000 + 页内序×100 + 列码` | `100003` = 页内第 0 行「编辑」 |

列表类**列码约定**（各行复用同一套）：

| 列码 | 含义 |
| --- | --- |
| 0 | 复选框 / 开关 |
| 1 | 减 `[-]` |
| 2 | 加 `[+]` |
| 3 | 编辑（进二级面板） |
| 5 | 复制 |
| 6 | 粘贴 |
| 7 | 删除 |

字段类面板（如面板 11 音符设置）可自定列码，但**必须在面板表头注明**（例：`±精细 1/2、±粗调 3/4、[x] 重置 5、进入子面板 6`）。

菜单系统**谱面总表**（页面 19）的行用「列码 1 = 游玩（行主操作）、列码 3 = 编辑」，行值 = `(1000+页内序)×100 + 列码`，页内序 0..9。

**页码不进值**：翻页值固定（如 `11601/11602`），页码存在 `notes_page`/`sel_page` 等 storage 字段里，处理器用 `页号 × 每页数 + 页内序` 还原真实下标 —— 同一套行值得以跨页复用。

#### 新增按钮流程（checklist）

1. **查重（必做）**：确认目标值未被占用 —— 既查发射点，也查处理点：
   - `grep -r "editor_click set <值>" data/`（谁发的）
   - `grep -r "matches <值>" data/`（谁处理的；**注意范围写法**，`11301..11305` 之类会“吞掉”里面的值）
   - **宏参数注入型（容易漏）**：按钮值不一定写在 click_event 里，也可能是 `data modify storage rhythm_axe:prop <key> set value <值>` 再由宏函数 `editor_click set $(<key>)` 拼出（例：位置三轴的 `bxm..bzp2` → `note_pos_row`）。搜 `grep -rn "set value <值>" data/` 确认。
   - 也可以直接搜号段号：`grep -rn "matches 12\|matches 13" data/`
   - **计算型（最易漏，会直接导致“点了提示该按钮不属于当前面板”）**：列表行按钮常常是**算出来的**，文件里根本没有 `editor_click set <数字>`。典型写法：
     ```mcfunction
     scoreboard players set #temp_cursor editor 600      # 基数 = 旧号段，改这里！
     scoreboard players operation #temp editor += #temp_cursor editor
     scoreboard players add #temp editor 1600           # 复选框基数
     ```
     查这类用 `python scripts\scan_legacy_button_values.py`（扫「常量赋值落在旧号段 / 行内裸旧号 / set 值不在任何守卫段」）。**只 grep 字面量一定会漏。**
   - 自动化：`python scripts/audit_injected_trigger_values.py`（全局扫描孤儿值，已识别宏拼接如 `set 1128$(index)`）
2. **选定行号与列码**：先确定按钮属于哪个面板（`current_panel` 号），在该面板号段内挑一行；同一行加新按钮就取下一个空闲列码。新开一行时行号取该面板已有最大行号 +1（保持可读）。
3. **写发射点**：在渲染该面板的 mcfunction 里给按钮 `click_event` 写 `/trigger editor_click set <值>`。
   **菜单系统页面**（如谱面总表）同流程，但计分板换成 `menu_click`、守卫写在该页面自己的 `panelN.mcfunction` 里（见《菜单系统（菜单层）》）。
   - 灰按钮（不可点）= **不带 `click_event`**，而不是灰色仍可点。
4. **写处理分支**：在 `editor/menu/panel/panelN.mcfunction` 里加 `execute if score #click_value editor matches <值> run function <处理函数>`。
5. **同步守卫**：若开了新行/新段，同步 `panelN` 顶部**两行白名单守卫**的号段（否则按钮点了只会提示“该按钮不属于当前面板”）；若落在已有范围里则无需改。
6. **更新文档**：同步本文件对应面板的 trigger 表（值 + 操作说明）。
7. **校验与实测**：`/reload` → 桥接实测点击 → 跑 `scripts\check_all_macros.ps1`（必须 0 错误）；改过/搬过按钮值后再跑这两条：
   - `python scripts\check_all_panel_coverage.py`（全面板 `emit ⊆ 守卫 ⊆ 分支` 审计，查「无守卫 / 有守无分支 / 来源面板无分支」三类问题）
   - `python scripts\scan_legacy_button_values.py`（抓**计算型 / 残留型**旧值，即上面第 1 步说的“算出来的按钮值”）
   ⚠️ 该审计只做**值级覆盖**检查，查不出「条件组合漏分支」这类语义问题（例：批量+绝对模式下 `prop.xcomp` 少写一个分支会让 `[x]` 消失），值级通过后仍需按模式组合逐项核对 + 实测。

#### 常见坑

- **撞号 = 双触发**：曾因 `842~855` 与面板 13 的 `830~851` 重叠，同一值既改判定位置又打开编辑对话框。新增必查重。
- **守卫是白名单**：忘加号段 → `unless ... matches` 全部命中 → `wrong_panel` + `return fail`，表现为“点了没反应 / 提示该按钮不属于当前面板”。
- **跨行范围迁移要拆**：旧范围映射到多段新行时（如 `768..781` → 6 行新值），一条 `execute` 必须拆成多条，不能仍写一个大范围。
- **动态行用页内相对值**：页码只由翻页处理函数改，处理器要用 `页号×每页数 + 页内序` 还原。
- **宏参数缺失会静默失败**：`function X with storage` 若 `#arg` 声明的键不存在，整个调用不执行（“点了没反应”的常见根因）。
- **按钮值可能不是字面量**：存在两种“隐藏”写法 —— ① 宏参数注入（`prop.<key> set value N` + 宏内 `editor_click set $(<key>)`，如位置三轴的 `bxm..bzp2`）；② 宏拼接（`editor_click set 1128$(index)`，实际值 11280~11289）。**只 grep `editor_click set` 会漏掉它们**；改号/迁移时必须一并处理，否则守卫换了新号而按钮还在发旧号 ⇒ 点了提示“不属于当前面板”。
- 每批改完 `.mcfunction` 必须 `/reload` 并跑宏检查；加载失败只进游戏日志（`Failed to load function`）。

> **【整理音符顺序】（2026-09-14 新增；2026-09-15 从面板 2 行108 迁到主菜单行108，值不变 `10801`）**：把工作副本的 `notes` 按 `time` 升序重排（相邻交换 + 回退的冒泡，**稳定**：等刻不交换、保持原相对顺序）。
> **它修的是什么**：批量修改的「判定时间」（`batch_apply_one`）是**原地改 time**，只改选中子集、不重排数组 → 选中组一挪动就会跨过没被选中的邻居 → 局部逆序（回退量 = 你设的增量）。
> 实测：一次「9 个染色玻璃 −6 刻」的批量编辑产生了 6 处逆序；谱面里累计出现过 11 处（含快照窗口之前遗留的 5 处）。
> **为什么必须修**：`insert_find`（遇到第一个 `time` 更大就插 → 插入点错、逆序自我累积）、`time_select` 的**二分查找**（范围选择边界错）、`sel_rebuild`/活跃列表（列表顺序倒挂）、出生游标 `#vis_next` / `tick_birth_*`（可能提前停、漏生音符）都默认 `notes` 升序；判定本身按各自 `time` 比较播放头 → 不受影响（所以一直没被察觉）。
> 批量确认（`batch_confirm_go`）在改过判定时间后会**自动**调用 `order_repair`；本按钮用于手动排查/修复历史遗留逆序。
> 修复会改变数组下标顺序 → 处理函数做完 `commit` 后立刻 `refresh`（重建视觉/选区/guide_prev），面板渲染推迟到下一刻。
> **保存时自动执行（2026-09-15）**：`editor/file/save` 开头会**无条件**跑一遍 `order_repair`（先修好顺序再落盘）；四个保存入口（主菜单【保存谱面】/【保存并退出】/另存 /【切换谱面】保存）都走 `file/save`，所以都会生效。确有交换时保存末尾额外提示「保存前已自动整理音符顺序：交换 N 处」并 `refresh`（`#vis_next` 出生游标等按下标的缓存要按新顺序重算）。两者都不建历史快照（保存本来就不进历史），按钮本身保留供手动排查。

#### 锚点（镜像 / 旋转的中心，2026-09-17 新增）

镜像 / 旋转的**中心**不再由算法临时现算，而是一个显式的「锚点」：

- **真值 = 世界里的实体**（`item_display`，tag `editor_anchor`；**连锁命令方块、边长 0.25 格**；**旋转默认单位四元数 `[0,0,0,1]`、缩放默认 `scale 0.25`，且数据包从不改写这两个字段**（`anchor_move` 只同步 `item.id` / `Glowing` / 发光颜色）—— 它们代表「用户手动给锚点摆的朝向 / 大小」，是《应用锚点变换》（`11511`）的变换源：**旋转 = `transformation.left_rotation`，缩放倍数 = `transformation.scale × 4`（三轴各自独立）**（默认 `[0.25,0.25,0.25]` ⇒ 各轴 ×1 不缩放；某轴 0.5 ⇒ 该轴 ×2、0.125 ⇒ ×0.5；每轴上限 ×4）；**发光颜色跟随状态**：红 `#FF5555` = 自动跟随 / 蓝 `#5555FF` = 已被手动改过，**与面板按钮同色**）。**不存 storage** —— 谁用什么方式挪它都算数（`data modify entity … Pos`、玩家手拖、其他模组都行）。
- **自动跟随**：锚点只在**选区重建**（`sel_rebuild`）时被搬回**选中音符判定位置的包围盒中心**。`sel_rebuild` 的触发点 = 勾选 / 去选 / 选区工具确认 / **每次 `editor/refresh` 的末尾**（`visual/refresh` 末行无条件调 `sel_rebuild`，只有「只动播放头」的快进快退 / 跳转 / 进度条点击会设 `prop.refresh_skip_sel` 跳过——那种刷新几何没变，锚点本来也不需要动）⇒ 编辑 / 批量 / 镜像 / 旋转 / 撤销之后锚点都会自动跟上。所以「没人动过锚点」时镜像 / 旋转结果与旧实现**逐位相同**（旧公式 `min+max−old` ≡ 新公式 `2×中心−old`）。
- **手动改过就不再跟随**：每次**自动摆放**时把该位置记在实体上（`data.anchor_cx/cy/cz`，int ×100，见 `anchor_mark_auto`）；下次同步时**拿实体当前 Pos 与这份记录比**，任一轴相差 > 0.05 格 ⇒ 判定「用户挪过锚点」→ 打 tag `editor_anchor_manual`，此后选区变动、旋转都不再搬动它；判定结果持久化在实体 tag 上 ⇒「改过一次就永远算改过」，不用额外的 storage 状态。
  - ⚠️ **基准绝对不能拿「当前包围盒中心」**（2026-09-17 修正，用户实测「选完第一个音符、没动过锚点，选第二个就被判成动过」）：选区一变中心就变、锚点却还停在旧中心 → 差 >0.05 格 → 误判。基准必须是**上次自动摆放的位置**（也就是锚点自己上次被摆到哪里）。
  - 旧实体兼容：实体上没有 `data.anchor_c*` 记录时（或记录为哨兵）退回旧口径（与当前中心比），保证那时用户摆的位置不会被吞。
- **按钮 `11510`【⌖】**：任何时候可点。**红** = 自动跟随中；**蓝** = 已被手动改过；悬停提示「重置锚点位置（镜像/旋转的中心回到选中音符判定位置的包围盒中心）」。点击 = 清掉锚点（含 manual 标记）→ 按当前选中包围盒中心重建 → 重绘当前列表（回到自动跟随）。因为重建是 `kill` + 重 `summon`，**用户手动摆的旋转 / 缩放也一并回到默认**（单位四元数 + `scale 0.25`）。**锚点实体自己的发光颜色也跟着变**（红 ↔ 蓝，与按钮同色），不用看聊天栏就知道当前是哪种状态。

#### 应用锚点变换（按钮 `11511`，2026-09-18 新增）

把锚点当前的**缩放 + 旋转 + 相对包围盒中心的位移**当成**一个整体变换**，一次套到所有选中音符的判定位置上：

$$P' = R \cdot S \cdot (P - C) + A$$

- $C$ = 选中音符**判定位置的包围盒中心**（每轴 `min + (max−min)/2`，×100 定点；`anchor_center` 一次遍历算出三轴）
- $A$ = **锚点实体位置**（×100 定点；`anchor_read` 读；实体不存在时退化成 $A=C$）
- $R$ = 锚点的 `transformation.left_rotation` 单位四元数 → 旋转矩阵（`anchor_matrix`；右手法 / 几何主动旋转，与旧的 15°/45°/90° 按钮同向）
- $S = \mathrm{diag}(s_x, s_y, s_z)$ = **三轴独立的缩放**：$s_{axis}$ = **锚点 `transformation.scale[axis] × 4`**（`anchor_matrix` 里**按列折进矩阵**：把矩阵第 $j$ 列整体乘 $s_j$ ⇒ 等价于先把 $(P-C)$ 各轴分别缩放再旋转，定点 ×1e4，每轴夹取 0..4）。默认 `scale [0.25,0.25,0.25]` ⇒ 各轴 ×1；某轴设 0.5 ⇒ 该轴 ×2、0.125 ⇒ ×0.5

**按钮位置 / 样式**：列表底部第二行（行 `115`）第 11 个 —— 共用组 `11511`（面板 10 / 18 共用；上一个号 `11510`【⌖】，下一个空号 `11512`）。文字`【应用锚点变换】`，悬停提示写完整语义；**无选中音符时变灰**（仅显示、点不动）。整次操作走 `file/begin`…`commit`（**一次快照可撤销**）。

**开关键语义**（与镜像 / 旋转组其它按钮不同，这里只有 `[S]` 参与）：

- `[S]` 开 → `start_pos`（来向偏移）也按同一个 $R \cdot S$ 变换（绕**该音符自己的判定位置**、不平移）⇒ 来向跟着一起转 + 三轴缩放
- `[X]` / `[Y]` / `[Z]` **不参与** —— 这里的变换是完整 3D（四元数），按轴拆开会失真；要按轴转就用 `11507`/`11508`/`11509`

**自己定缩放 / 旋转**（不提供按钮，按用户要求「我自己转」）：锚点是 `item_display`，直接改实体字段即可 ——**数据包从不改写这两个字段**（只写 `item.id`/发光），所以改完一直有效，直到下次 `summon` 重建：

```
/data modify entity @e[tag=editor_anchor,limit=1] transformation.left_rotation set value [0f,0.70710678f,0f,0.70710678f]   # 绕 Y 90°
/data modify entity @e[tag=editor_anchor,limit=1] transformation.scale set value [0.5f,0.5f,0.5f]                        # 三轴都 ×2
/data modify entity @e[tag=editor_anchor,limit=1] transformation.scale set value [0.5f,0.25f,0.25f]                      # 只把 x 拉成 ×2（y/z 不变）
```

**应用之后锚点完全重置**（`anchor_rebuild_at_center`：`kill` → 按**新**几何重算包围盒中心重建）⇒ 位置回新中心、旋转回单位四元数、`scale` 回 0.25、清 `editor_anchor_manual`、变回红。⇒ **每次应用都是一次性输入**，想再来一次就重新摆锚点。

**实现**：`editor/menu/note/panel/note_panel_anchor_apply.mcfunction`（入口：无选中报错退出 / `#op_count` / `op_announce`；> 50 音符走 `_next` 跨刻）、`_go`（参数 → 扫描 → `commit` → 锚点重建 → `refresh`）、`_drive`（普通驱动器，防宏递归幽灵）、`_leaf`（宏叶子：`selection[idx]` → `find_by_id` → `_one`）、`_one`（定点算 `P'`，写回 `double 0.01`）。**溢出前提**：$|P-C| \le 100$ 格且每轴倍数 ≤ ×4 ⇒ 矩阵项 ≤ 4e4、三轴定点乘积和 ≤ 1.2e9 < 2³¹ ✓（`#scl1/#scl2/#scl3` 已各夹到 0..40000）。

### 面板通用机制

- **面板隔离**：`maps.editor current_panel`（1 主菜单 / 2 谱面设置 / 3 时间点列表 / 4 时间点面板 / 5 事件列表 / 6 事件面板 / 7 查找 / 8 退出确认 / 9 另存确认 / 10 音符列表 / 11 音符设置 / 12 全局击打音效 / 13 击打视效 / 14 击打事件二级菜单 / 15 切换谱面确认 / 16 删除谱面确认 / 17 回收站 / 18 已选定音符列表）。**页面 19 属于菜单系统（谱面总表）**，不是编辑器面板：页面号存 `rhythm_axe:map_list.panel`，点击由**菜单层** `menu/consume` 分发（见《菜单系统（菜单层）》《谱面总表（菜单系统页面 19）》）。点击按钮时只执行当前面板自己的按钮值段，其他面板的按钮会提示 `[编辑器] 该按钮不属于当前面板`（黄色）而不执行，防止串面板误操作。**号段分配、列码约定与新增按钮流程见上文《trigger值》一节。**
- **操作反馈**：操作完成且返回上一级菜单时，先写 `maps.editor feedback`，面板清屏后先显示 `[编辑器] {反馈}`（黄色纯文本）再显示新面板，保证反馈不会被清屏顶掉；纯提示性文本（灰色斜体）单独成一条消息，不含点击事件
  - 反馈行末尾**同时**附【撤销】【重做】两个按钮（值 `8` / `9`，任意面板可用；点击后回 `undo_panel` 操作面板）：可撤销 = `history_cursor ≥ 1`、可重做 = `history_cursor < history 长度−1`；**不可用的那个变灰且不带 `click_event`**（点了没反应，也不会弹“该按钮不属于当前面板”）。例：`[编辑器] 已撤销：创建音符盒 【撤销】【重做】`

- **播放进度 bossbar**：`rhythm_axe:editor_progress`，仅播放时显示，最大值取当前谱面结束时间，播放头逐刻推进，到末尾自动暂停

- 所有按钮由方括号（简单按钮英文方括号，有字的用中文方括号）括起来，能按的是绿色，因为值域限制等原因不能按的是红色

  - 输出反馈内容
  - 计算面板所需数据
  - 把所有空属性赋默认值
  - 输出面板内容

### 菜单系统（菜单层，2026-09-19）

聊天栏菜单 UI 的**独立层**，与编辑器（`editor_click`）、游玩系统并列，三者互不干扰。

| 组成 | 说明 |
| --- | --- |
| 触发计分板 | `menu_click`（trigger 类型；`load.mcfunction` 里 `add` + `enable @a`） |
| 临时分数板 | `menu`（菜单各页面自己的临时变量，与编辑器的 `editor` 分数板分开） |
| 检测 | `tick.mcfunction`：`execute as @a[scores={menu_click=1..}] run function rhythm_axe:menu/consume` |
| 分发层 | `rhythm_axe:menu/consume`：读值 → reset → 重新 enable → 播 UI 点击音 → **按值所属号段**分发给页面（2026-09-26 起不再看 `map_list.panel`，这样广播给多人的页面各点各的） |
| 页面 | 19 = 谱面总表；规划中 20 = 难度选择 |

- 页面是**顶级目录**（`map_list/`），入口直白：`/function rhythm_axe:map_list/open`。
- **新增页面流程**：① 写页面渲染 + `页面名/panel/panelN.mcfunction`（两行守卫白名单 + 分支）② 在 `menu/consume` 加一行 `execute if score #menu_panel menu matches N run return run function …` ③ 按钮发 `trigger menu_click set <值>`。
- 值仍按 spec v2 编号（值 = 行号×100 + 列码），但**守卫白名单写在页面自己的 `panelN.mcfunction` 里**，与编辑器面板互不干涉。

### 谱面总表（菜单系统页面 19，已实现 2026-09-19）

把所有"已保存的谱面"列成一张表，每行 `{标题} - {作者}【游玩】【编辑】{mapid}`，供玩家选谱开局 / 选谱进编辑器。

**它是菜单系统的一个页面，不是编辑器面板**：不写 `maps.editor`，自带会话状态 `rhythm_axe:map_list`；**没有单人锁**（谁点开谁能用，多人同时打开共享页号，各自点击各自生效）。

**点击走菜单系统自己的通道**：按钮发 `trigger menu_click set <值>`，`tick.mcfunction` 检测后交给分发层 `rhythm_axe:menu/consume`（临时分数存分数板 `menu`），**完全不经过 `editor_click` / `editor/menu/consume`**。

| 项目 | 说明 |
| --- | --- |
| 入口 | `/function rhythm_axe:map_list/open` —— **无条件打开**（编辑中也能翻看/查谱面，2026-09-26 用户定）；「编辑中不能开局」的拦截改放在【游玩】按钮（`map_list/maps/play`） |
| 收起 | **没有【关闭】按钮**（聊天栏面板本来也没有"窗口"可关）；进游戏/编辑器时自动 `map_list/close` 收起，`/reload` 也会清掉 |
| 每页行数 | 10 行；页号 0 基，存**玩家自己的** `menu_page` 计分项（2026-09-26 由全局 `map_list.page` 改为按玩家；**页码不进按钮值**，行值跨页复用） |
| 排序 | **索引顺序**（= 入队先后），不做排序 |

**数据结构**

```plain
rhythm_axe:maps
└── index[]           [列表]  谱面索引（mapid 字符串，按入队顺序）；总表就按这个顺序显示
rhythm_axe:map_list
├── open: 1b          [Bool]  菜单是否开启（menu/consume 的守卫）
├── panel: 19         [Int]   当前面板（规划中：20 = 难度选择）
└── page: 0           [Int]   总表当前页（0 基）
```

**索引（`maps.index`）—— 总表的名单从哪来**

一张谱面 = 一个独立命令存储 `rhythm_axe:maps.<mapid>`，**游戏内无法枚举 storage**，所以名单由索引列表维护，并自动跟随谱面生命周期：

| 时机 | 调用 | 效果 |
| --- | --- | --- |
| 【保存谱面】(`file/save`) | `maps/index/index_add` | 入队（幂等，已存在不重复加） |
| 【删除谱面】(`file/delete`) | `maps/index/index_remove` | 出队（进了回收站就不在总表里） |
| 修改谱面 id (`map_rename`) | `maps/index/index_rename` | 旧名出队 + 新名入队（⚠️ 谱面会挪到列表末尾） |
| 回收站【还原】(`trash_restore_go`) | `maps/index/index_add` | 入队 |
| 打开大厅 | `maps/index/index_sync` | 自检：剔除"正式存储已不存在"的条目（重建列表） |

- **一次性导入**：索引机制上线前就存在的谱面用 `/function rhythm_axe:maps/index/index_bootstrap` 补登记（幂等，可重复跑）。
- 实现 = `普通函数驱动器 + 宏叶子`（`index_{add,remove,sync}{,_drive,_leaf}` + 共享取项助手 `index_get`）；
  查重/比较走"复制到 `prop` + 复合标签匹配"（字符串比较的既定写法）。

**渲染**

- 清屏 → 标题 `====  节奏地图谱面总表 Rhythm axe Maps  ====`（gold bold）→ 最多 10 行 → 页脚
- 行 = `{标题} - {作者}【游玩】【编辑】{mapid}`：标题经 `utilization/title_comp` 归一化后原样显示（保留样式）、作者 `gray`、按钮 `【游玩】`green / `【编辑】`aqua、末尾 `{mapid}` 用 `dark_gray`（暗色，方便对着 id 直接跑命令）（JSON 组件字符串 / 裸纯文本 / 复合·列表 三种形态都能显示），作者用宏注入
  （⚠️ 作者名里含双引号会破坏整行 JSON → 需要写成 JSON 组件字符串）
- 渲染链（三层，宏参只能"调用时解析"，运行时读出来的值必须经 `prop` 传给下一次调用）：
  `list_drive`（普通驱动器，逐行）→ `index_get`（读 `index[i]` 到 `prop.mapid`）→ `list_row`（读标题/作者、生成标题组件与两个按钮值）→ `list_row_line`（宏叶子，出 tellraw）
- 页脚 = `【上一页】 x/y 共n张谱面 【下一页】`，**配色与事件列表翻页行一致**：可用 = `green`（带 `click_event` + hover）、禁用 = `red`（不带 click_event，点不动）；中间页码的数字 `white`、分隔（`/`、`共`、单位）`gray`。只有一页时两个翻页按钮都禁用
- 空表（0 张）时给一行灰字提示（页脚只剩页码）

**trigger 表（菜单系统页面 19，计分板 `menu_click`）**

### 时间点

- 当点击编辑器主菜单的【时间点】按钮，弹出时间点列表


> █的颜色会随着时间点的颜色变化
> 【复制】：点击后聊天栏提示“已复制时间点信息”，不刷新面板

**红线/绿线 自动计算**：在以下两种情况会把时间点判为红色：
    - BPM直接发生变化
    - 有tick rate 指令执行：当前时间点与前一个时间点相比，其最终 tps 发生变化
    其余情况下该时间点为绿线。
> 红线：bpm或者tps发生变化的时间点，并且认定为新的小节
> 绿线：bpm和tps不变，但是 每小节刻数/每拍刻数/偏移量 发生变化
> 最终 tps = bpm × tpb ÷ 60；判定是否变化时用 ×1000 整数比较 `bpm×tpb×1000`，避免浮点误差

- 使用时间点工具或者点击时间点列表的编辑按钮，在聊天栏弹出统一的控制面板：

```panel

 时间：128（当前互动位置，可手动调整）
 [-][+]【使用当前时间】  // 每次 ±1 刻
 BPM：[编辑数值]  // 对话框输入小数（如 175.000），原封不动存储为 Float
 拍号：[-] 4 [+]
 每拍刻数：[-] 8 [+]
 偏移量：[-] 0 [+]
 判定缩放倍数：[-] 1 [+]  // >=1，作用于该时间点起效范围内音符的判定区间（见[音符→属性→判定区间缩放倍数](音符.md#判定区间缩放倍数)）
 颜色：R（红线）← 自动计算
 【上一个时间点】【下一个时间点】← 如果存在则绿色，不存在则红色
 【取消】【确认新增】【复制】【粘贴】         ← 互动的是空白区域或者点击时间点列表的【新增一个时间点】
 【取消】【确认】【复制】【粘贴】【删除】       ← 互动的是已有时间点
```

> 若互动位置为**空白区域**（当前无时间点）：面板底部显示"确认新增"，确认后在当前 time 新增一个时间点，按 time 升序插入数组
> 若互动位置为**已有时间点**：面板底部显示"确认"和"删除"。点击"确认"更新该时间点的值；点击"删除"进入二次确认（首个 time=0 不可删除，提示"不能删除曲目起始时间点"）
> 【粘贴】：如果剪贴板有复制好的时间点信息则绿色，点击后将剪贴板上的信息粘贴给正在编辑的时间点，聊天栏提示“已粘贴时间点信息”并且刷新面板

- 点击【批量编辑】时会弹出一个“批量编辑音符”的面板，其内容与音符属性控制面板相同，不过其中显示的数值均为“缺省”，第一次点击面板中的按钮对数值进行修改时会给数值赋默认值。只有在批量编辑中修改的属性才会被写回音符，所有音符写入相同值，未修改的属性保持原值不变；
- 批量编辑里的**「相对/绝对」四个字段**（判定时间 / 大小 / 判定位置 / 起始位置）与同值字段一样，用 `editing.batch_set.<字段>` 标记「本项是否被改过」：
  - **相对模式（进入批量时的默认）**：改的是 `editing.rel.delta.<字段>` 增量，确认时对每个音符累加（未改过的字段增量恒为 0，天然无影响）
  - **绝对模式**：改的是 `editing.temp.<字段>`（要统一写入的值），确认时**只对已打 `batch_set` 标记的字段**覆盖；未标记的字段保持各音符原值 —— 与同值字段（类型 / 颜色 / 基础寿命 / 持续时间…）的处理一致
  - 行首 `[x]` = 取消本项修改：相对模式清增量，批量下同时清 `batch_set` 标记；**批量模式没有 `editing.orig`（只有单音符编辑才有），所以绝对模式下「是否已改」一律看 `batch_set`**

#### 时间段选择（蹲下 + 右键）

使用选择工具，还可以选择某一时间段（或某一刻）内的音符：

- **蹲下 + 右键**（金斧头）：第一次把**当前播放头**设为**入点**，第二次把当前播放头设为**出点**，并按下面的判定选中音符（出点小于入点时自动取 min/max，所以反向拉也行），随后弹出「已选定音符列表」；区间内没有音符则提示并回主菜单
  - 判定依据：**判定时间 `time` 落在 `[入点, 出点]` 内（含两端）**；或**长音符**（**仅混凝土**，`type` 3 且 `duration ≥ 1`）的自有跨度 `[time, time+duration-1]` 与区间**有交集** —— 这样「判定时间在区间外、但持续时间延伸进区间」的混凝土也能被选中（玻璃不适用此条）
- 入点/出点会**保留显示**在 mod 可视化时间轴上：**七行贯通的半透明色带**（从入点那一列的左缘一直盖到出点那一列的**右缘**，最后一列整列覆盖）+ 两端各一个**拉满七行的大中括号**（竖杆 + 顶/底横臂、中间留缝）。括号方向由区间 `min/max` 决定 —— 所以**第二次点的刻比第一次早时会自动翻过来**，两条括号始终把范围夹在中间；只设了入点时先画左括号（等待出点的反馈）。色带与中括号**画在最上层**（盖住刻度线/音符/数量角标，仅播放头在其上）；括号样式：**上下两半各占 2 行高**（竖杆 2px + 顶/底横臂 5px），中间留大空隙（约 3 行）；位置在色带**内侧** —— 左括号贴左端刻度线**右边**，右括号再往右 1px、**压到右端刻度线上**
- 设完出点后**再次蹲右键 = 开启新一轮**：当前播放头变新入点，旧的出点与上一轮选中一并清掉
- 站立右键仍是原来的立方体两点框选，两者状态互不干扰（`select_tool` / `time_select` 分开存）；退出编辑器、切谱面、重给工具都会清掉入点/出点

#### 工具常驻机制（动态改名/换造型）

- `function/tick.mcfunction`（每 tick，`#minecraft:tick`）调用 `editor/tool/tool_regular_tick` → `tool_regular_apply`：对每个激活编辑器玩家，先在 `tag editor_tool_was_sneak` 里比对蹲下状态（**未变化直接跳过整轮**），变化时才写入 `#tool_sneak` 并检查**可能放工具的 11 个槽**——快捷栏 `container.0-8` + 选择工具槽 `container.9`（`give_select_tool` 用，= 主背包第 1 格）+ 副手（非编辑工具的槽位不调宏），逐槽调 `tool_regular_slot`（按 `custom_data` 标记分派）→ 对应 `tool_XXX_update`：
  - 方向工具（带 `editor_tool_fwd`/`editor_tool_bwd`/`editor_tool_model`/`editor_tool_state`）：`tool_dir_update` → 宏 `tool_dir_write` 重写物品名（【前进XX】/【快退XX】）
  - 事件/时间点工具（`editor_tool_timing`）：`tool_timing_update` → 宏 `tool_timing_write` 切换名称/造型（命令方块矿车↔时钟）
  - 选择工具（`editor_tool_select`）：`tool_select_update` → 宏 `tool_select_write` 切换名称/造型/名字颜色（【选择工具】金斧头·绿名 ↔【时间段选择】钻斧头·淡蓝名，两者都带灰字提示）；蹲下时 `cursor_tick` 额外把黄绿玻璃清掉
  - 返回开头（`editor_tool_timeline_start`）→ `tool_start_update`；播放速度（`editor_tool_timeline_speed`）→ `tool_speed_update`；配对音符（`editor_tool_note_pair`）→ `tool_note_update`
- **这些槽里的工具一起切换**（不只手持槽）：蹲下时每个工具都换成蹲下态，松开立刻换回（无需改变手持槽）；**其余背包格不放工具、不扫描**（玩家手动把工具拖到主背包第 2 格之后时不会跟随切换）
- 仅在**该槽** `editor_tool_state` 与目标状态不符时才重写，避免每刻无谓重写
- 所有 update/write 均以 `slot` 为宏参数（`tool_regular_slot {slot:"container.N"}` → `tool_XXX_update {slot:"..."}` → 宏 `tool_XXX_write {slot:"..."}` 内的 `item replace entity @s $(slot)`），故可作用于任意槽位；**含 `$(...)` 的命令行必须以 `$` 开头**（MC 宏规则）
- ⚠️ **性能**：宏调用 ≈1ms/次，故只在蹲下状态变化时整轮改写、且非工具槽不调宏；`give_note_tool` / `give_timeline_tool` / `give_select_tool` 末尾会 `tag @s remove editor_tool_was_sneak`，保证给予后（即使玩家正蹲着）下一 tick 重算一次

> 选择工具的**时间段选择**（蹲下右键定入点/出点、按判定时间选中区间内音符）见上文《选择工具》一节的「时间段选择（蹲下 + 右键）」。

## 通用机制

贯穿整个编辑过程、不属于某个特定步骤的机制。

### 字符串输入

谱面id、标题、作者、音乐文件、预览音频、BPM、事件指令等字符串/数值需要手动输入时，统一使用**对话框（dialog）**方案。

**输入流程**：

1. 面板点击【编辑文本】/【编辑数值】→ `dialog show @s <命名空间>:<对话框>` 打开对应输入对话框
2. 玩家在文本框（`text` 输入控件，支持多行）输入内容
3. 点提交按钮 → 对话框的 `dynamic/run_command` 把输入拼进函数调用（如 `/function rhythm_axe:xxx {"value":"$(raw)"}`），以玩家身份执行
4. 接收函数把 `$(value)` 按规则处理后写入目标字段，再刷新原面板显示

**输入能力边界**（实测）：

- 普通单行文本 ✅
- 多行文本 ✅（提交时换行被转义为 `\n` 字面量，文本压缩为一行）
- 引号 `"` ⚠️ 裸引号会导致宏命令语法错误，**必须手动输入转义形式 `\"`**（存储的是真正的引号）
- 长文本 ❌ 提交走聊天命令（`chat_command` 数据包），有长度上限；**函数文件"单命令不受 32500 限制"不适用于对话框**，超长输入会断连。实际上限以测试为准
- 含引号/超长的复杂指令（如 JSON tellraw）：不建议用对话框输入，改由谱师**创建 function 文件**并在面板中引用

**写入前处理**：

- **标题（JSON 文本组件）**：输入 JSON 组件（对象 `{"text":"标题","color":"red"}` 或带引号字符串 `"新手教程"`），存为字符串；**不能输入裸纯文本、组件不能含空格**（显示用宏传 `$(title)` 作为组件参数解析，裸文本/含空格会失败）；显示处（主菜单/谱面设置面板/bossbar/开始编辑反馈/游玩结算）全部宏传解析，与游玩时一致
- **BPM**：存储为 Float 小数（`bpm: 175.0f`），对话框直接输入小数（如 `175.000`），原封不动存储
- **事件指令**：输入命令字符串；含引号时用 `\"` 转义，或走 function 文件
- 整型数值输入写入前做值域校验（值域见各字段说明）

**异常处理**：对话框原生支持 Esc 关闭（`can_close_with_escape`）、可设为不暂停游戏（`pause:false`）；打开新的输入对话框会覆盖旧的，无需额外超时管理。

**注意**：对话框定义文件（`data/<命名空间>/dialog/*.json`）只在服务端启动时加载一次，修改后需**重启服务端**，`/reload` 无效。

**对话框与聊天栏面板的职责划分**：

- 聊天栏 tellraw 面板负责**动态展示与操作**：显示当前值、`[-][+]` 加减、需要随游戏状态实时刷新的内容（改 mcfunction + reload 即可）
- 对话框负责**静态输入**：文本/数字/单选/开关等原生输入控件；面板上的【编辑文本】是打开对应对话框的入口
- 分配优先级：先看使用场景哪个更直观、更容易；其次考虑性能消耗与实现难度

- 从osu的物件时间轴和剪辑软件的时间轴上获取的灵感
- 对谱面信息和前后一段时间内的物件进行图形化的实时显示
- 可以在上面进行编辑器的多数操作
- 整个界面可以被更改位置

### 实现细节

- 不止按钮有交互实体，时间轴也用许多交互实体拼起来，除了节奏刻度显示轨道，每个轨道每个单位格上都有一个交互实体；与不同位置的交互实体进行交互可以有不同操作，如在五种音符的时间轴上交互就是添加/编辑/删除音符，在时间点/事件点轴上交互就是添加/编辑/删除时间点/事件点
- 时间轴上各物件的占格：时间点、事件、五种音符都只占 1 个单位格；混凝土按持续时长占多个单位格
- 与时间轴交互实体交互，编辑的是**交互位置**的物件；使用对应工具（时间点/事件工具），编辑的是**当前播放头位置**的物件
- 如果一刻内有多个同类型音符，在时间轴上只显示一个音符，
  在音符的右下角用文字展示实体（展示实体scale = 0.1）显示音符数量
- 如果一刻内的事件有多条指令，在时间轴上只显示一个事件，
  在事件的右下角用文字展示实体（展示实体scale = 0.1）显示事件数量
- 小节线：如果一拍的开头是一个小节的开头，则会有一个白色染色竖线贯穿五条轨道，厚度0.02，高度0.313，宽度0.02
- 与时间轴上的音符交互可以选中音符，然后可以进行编辑等操作，选中后的音符不止在世界中会发光，在时间轴上也会发黄光
- 时间轴的显示长度
  -- 由全局设置决定，以0.0625格为一单位，以拍为单位显示，剩余空间不满一拍则不显示。
      如设置显示长度为32，则显示32刻的时间轴，正好能显示8tpb下的4拍；
      但是如果设置显示长度为30，则8tpb下只显示3拍；
- 当播放时，播放头在整条时间轴的前三分之一处，播放头不动，时间轴动（类似剪辑软件的时间轴）

## ★ 命令链与「分刻」政策（2026-09-12）

### 1. 命令链上限
`gamerule max_command_sequence_length` 在 `data/rhythm_axe/function/load.mcfunction` 里，**2026-09-12 由 200000 提高到 1000000**。
原因：谱面涨到 ~580 音符后，**单条** `refresh`（kill 全部实体后按 notes 重建视觉）或**单次**列表渲染各自就接近 20 万条命令，
200000 时**正常操作**也会被静默截断（日志 `Command execution stopped due to limit`，被砍掉的总是尾部：视觉重建 / 末尾的 `sel_rebuild`），
表现是「数据是对的、但世界里的音符不对劲」。提高后这条上限只当**失控递归的报警线**。

### 2. 重活与渲染不要同刻
上限变大只是兜底，不是许可证：主操作（含 `refresh`）+ 面板/列表渲染同 tick 会让那一刻明显卡顿，将来谱面再翻倍还会重现。
标准三拍：**主操作（含 refresh）→ `schedule ..._finish_next 1t`（收尾 + 反馈）→ `schedule ..._return_next 1t`（面板/列表渲染）**。
`schedule` 拉起时执行者是**服务端**（没有 `@s`），所以包装函数里必须 `execute as @a[tag=editor_active]`；跨刻参数用计分板/storage 传。

已分刻的流程：`翻转时间`/`翻转镜像`/`旋转`、`音符设置确认`、`批量确认`、`批量删除`、`批量剪切`、`行内粘贴`、
主菜单(`menu/main_next`)、返回当前面板(`menu/resume_next`)、事件列表(`event_list_open_next`)、时间点列表(`timing_list_open_next`)、
`create_new`/`finish_open`（新建/打开收尾）、`map_panel_save`、`cycle_note_speed`、`jump_start`、`panel1`(行106 流速)。
故意不分刻的：`editor/tool/note_offset_go`（`refresh` 单独跑不超限，渲染的是单音符面板 O(1)）。

### 3. 大操作提示（处理音符数 > 50）
重操作入口一律拆成**三件套**：
- `<操作>.mcfunction`：前置 —— 数音符 → 写 `prop.op_label` → `function rhythm_axe:editor/util/op_announce with storage rhythm_axe:prop`
  → `#op_big=1` 时 `schedule <操作>_next 1t`，否则直调 `<操作>_go`（≤50 零延迟）
- `<操作>_go.mcfunction`：真正干活
- `<操作>_next.mcfunction`：`execute as @a[tag=editor_active] run function ..._go`

**为什么 >50 要推迟一刻**：同一条命令链里的 `tellraw` 会和重活一起被客户端渲染，玩家看不到「正在…」就先卡住了；提前一刻才看得见。
提示文案：`[编辑器] 正在 <操作名>（N 个音符），请稍候…`。已接入：批量修改、批量删除、批量剪切、翻转时间、镜像判定位置、旋转。

### 4. 复制 / 剪切 / 删除 的语义（2026-09-12 重构）
- **复制**：收集选中音符 → 写进 `maps.editor.clipboard`（不动谱面、不产生快照）。
- **删除**：`editor/note/delete/delete_by_ids` —— 按列表删，**只删原音符、全程不动剪贴板**（内部备份 + 收尾还原）。
- **剪切 = 复制 + 删除**：同一个收集过程产出 `clipboard`（保留，之后可直接【批量粘贴】）和待删下标，然后删原音符。
- 三者共用**同一套删除引擎** `editor/note/delete/remove_*`（倒序删除，避免下标漂移），收尾由 `remove_finish` 按 `prop.clip_action` 分派：
  `delete` → `delete_finish`（还原剪贴板 + 提示「已删除 N 个音符」）、`cut`/`batch_cut` → `cut_finish`（剪贴板保留 + 提示「已剪切 N 个音符」）。

> ⚠️ 踩坑记录：重构前是「删除 = 剪切 − 复制」（批量删除借剪切链路，收尾靠 `cut_finish` 顶部的一个 return 守卫分流）。
> 那个守卫判断的是 `clip_action`，而它上一行调用的收尾函数恰好把 `clip_action` 清掉了 ⇒ 守卫失效、掉进剪切尾部，
> 于是【批量删除】会先弹一句「已剪切 N 个音符」再弹「已删除」——玩家会去找一个根本不存在的剪切按钮。
> **教训：分流守卫不能依赖「被分支函数清掉的标志」；要分派就在唯一尾部按标志分派一次。**
## 多人协作（编辑器）

一个会话 = 一份 `maps.editor` 工作副本。**所有协作成员共享同一面板、同一播放头、同一选区/剪贴板/撤销栈**（= 一起编同一张谱）。

### 角色与 tag

| 角色 | 标识 | 说明 |
| --- | --- | --- |
| 编辑者（所有协作成员） | tag `editor_active` | 面板渲染 / 判定 / 工具 / bossbar / 时间轴 HUD / 音乐全都以它为准 —— **原单人代码 91 处 `@a[tag=editor_active]` 选择器零改动** |
| 会话主 | tag `editor_host` + `maps.editor.player` | 打开编辑器的人；**不可被踢**；事件链的代表对象；时间轴 HUD 的兜底目标 |

### 加入 / 退出

| 操作 | 做法 |
| --- | --- |
| 邀请 | 会话主持 **【协作·邀请】**（命名牌外观，放在**背包第 1 格**）**右键队友** |
| 踢出 | 手持它**蹲下右键**队友（物品外观同时变成 **【协作·踢出】** 屏障） |
| 收工 | 会话主正常退出（面板 8 → 确认）；退出时对所有人执行 `editor/coop/leave_core` |
| 补发工具 | `/function rhythm_axe:editor/tool/give_coop_tool` |

- 邀请/踢出都会**广播**给所有编辑者；被踢者会收到说明，他的编辑工具被收回、音乐被停。
- 加入时会把他的快捷栏/背包工具**覆盖**（与单人点【工具组】同款行为，不备份原物品）。
- 协作工具走 give 命令发放（不占快捷栏 0-8，不与音符工具组/时间控件组冲突）。
- **发放时机（2026-09-26 用户定）**：不再随打开编辑器自动发放（原先会无条件占掉背包第 1 格）⇒ 由**主菜单行 109【领取协作工具】**（`10905`）自愿领取；发放时会 tellraw 说明用途。补发/测试仍可直接调 `/function rhythm_axe:editor/tool/give_coop_tool`。

### 已知限制（刻意为之）

- **面板是共享的**：两人不能各看各的面板 / 各调各的音符（要那样得把 `maps.editor` 拆成 per-player，成本极大）。
- **全局临时量**：`prop.*`、`#xxx editor`、`undo.pre_snapshot` 是全局单例 —— 同刻并发靠上面的锁挡；连点时第二个人会看到「请稍候」。
- **锚点实体全局唯一**：两人同时用镜像/旋转会互相影响。
- **判定放宽**：真实判定里「任一编辑者看 / 点 / 站进判定区」即命中。
- **人数不设上限**：但每次渲染会逐成员重跑一遍（`note_list_open` ≈170ms/次）⇒ 人越多越慢。
- **临时面板不同步**：`resume` 对面板 8/15/16（退出/切换/删除确认）刻意回主菜单 ⇒ 别人点这些确认框时，其他成员看到的是主菜单（其余面板都能同步）。
