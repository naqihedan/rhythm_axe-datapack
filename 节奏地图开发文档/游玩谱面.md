# 游玩谱面

一张谱面以 `rhythm_axe:maps.<mapid>` 的形式存储在命令存储中。游玩部分把这份数据**读取成可玩的运行形式**：初始化运行状态 → 逐刻推进三条时间线 → 判定音符 → 结束结算。由统一的 function 入口启动，宏参数传入谱面 id。

## 运行时状态

一张谱面运行时的状态与谱面数据分离（数据只读，运行期不写回），由计分板和storage组成：

### play_state 计分板

一局游玩的所有运行时状态（运行标记、时间、游标、判定计数、分数等）都放在 `play_state` 计分板：

| 计分项 | 说明 |
| --- | --- |
| `is_running` | 运行标记：0/1，是否有谱面在运行 |
| `time` | 音乐时间轴，单位刻；`time == 0` 为音乐起点 |
| `#note_cursor` | 音符时间线游标 |
| `#timing_cursor` | 时间点时间线游标 |
| `#event_cursor` | 事件时间线游标 |
| `#judgement_scale` | 当前判定区间缩放倍数，随红线时间点更新 |
| `perfect` | 判定计数：Perfect |
| `perfect_early` | 判定计数：Perfect（early） |
| `perfect_late` | 判定计数：Perfect（late） |
| `good` | 判定计数：Good |
| `good_early` | 判定计数：Good（early） |
| `good_late` | 判定计数：Good（late） |
| `bad` | 判定计数：Bad |
| `miss` | 判定计数：Miss |
| `combo` | 当前连击 |
| `max_combo` | 最大连击 |
| `score` | 当前分数 |
| `highest_score` | 本次结算后的最高分副本（结算显示用；持久值存于谱面 storage `rhythm_axe:maps.<mapid>.highest_score`，每谱面独立） |
| `health` | 游玩血量（与玩家真实血量分离，判定扣血只扣它） |
| `damage_cooldown` | 扣血冷却计数器（>0 时每刻 -1） |
| `fc_ap` | FC/AP 标记：0=无 1=FC 2=AP |
| `auto` | 自动模式标记（0=关 1=开；start 从 `mods.auto` 复制，判定系统读取） |

### options 计分板

玩家可自定义的全局设置（开始游戏不重置，仅主动重置时恢复默认）：

| 计分项 | 默认 | 说明 |
| --- | --- | --- |
| `note_speed` | 16 | 音符速度（出生时刻 = time - note_base_life×16/note_speed） |
| `feedback_actionbar` | 1 | 判定反馈显示在物品栏上方 |
| `feedback_chat` | 1 | 判定反馈显示在聊天栏 |
| `detailed_judgements` | 1 | 结算时显示各判定的 early/late 细分 |
| `damage_cooldown` | 10 | 染色玻璃扣血冷却（刻） |
| `song_progress_display` | 1 | 显示歌曲进度条 |
| `song_progress_color` | 0 | 进度条颜色（0=白 1=粉 2=蓝 3=红 4=绿 5=黄 6=紫） |
| `debug_output` | 0 | 调试输出等级 |

> 结算权重（`1th_weight`/`2nd_weight`/`3rd_weight`，默认 2/1/0，存于 `score_calculate` 计分板）与评级线（`SS`/`S`/`A`/`B`/`C`/`Failed`，默认 100000/98000/94000/88000/80000/0，存于 options 计分板）见[设置](设置.md#设置)。

### 运行存储 `rhythm_axe:runtime`

游玩期间谱面数据的运行副本与宏参数传递通道都放在命令存储 `rhythm_axe:runtime`（`play/start_of_game/start` 从 `rhythm_axe:maps.<mapid>` merge 进来，运行期不写回源谱面）。它承担两类职责：

1. **谱面数据运行副本**：把 `maps.<mapid>` 整个根复制到 runtime，供主循环每刻读取（游标按数组下标推进）
2. **宏参数传递通道**：宏函数用 `function X with storage rhythm_axe:runtime` 传参，`$(变量)` 在**调用时刻**从 runtime 根（或指定子路径）快照——因此所有宏参数都必须由调用方**预先写入** runtime，函数内再写不生效

#### NBT 结构

> 图例：`{ }` = 复合标签（对象）　`[ ]` = 列表/数组　`★` = 字段分组

```
{ }  rhythm_axe:runtime：运行存储。
├── ★ 谱面数据（start 时 merge 自 maps.<mapid>）
│   └── 谱面共通标签[下方链接]
├── mods:                                [已废弃] 游戏模组开关改由 mods 计分板控制（start 复制到 play_state 同名项），不再存 storage
├── ★ 运行期附加字段（start 写入）
│   ├── mapid: "new_beginning"           [字符串]  谱面 id（合并后重写，供宏/结束清理用）
│   ├── prev_gamemode: 0                 [Int]     玩家进入前游戏模式（0=生存 1=创造 2=冒险 3=旁观；结束还原用）
│   ├── spawn_x / spawn_y / spawn_z      [Double]  spawn_pos 数组拆成的标量（宏传送用；宏键不支持数组下标）
│   └── hit_events.<note_id>             [List]    该音符的击打事件（summon 存，判定/清除时删）
│       └── { }                          {command, enabled:{spawn,bad,good_early,...}}

│   ├── scan_idx: 0                      [Int]     scan_birth 遍历音符游标（= #scan_index）
│   ├── note_idx: 0                      [Int]     spawn 遍历游标（= #note_cursor）
│   ├── tp_idx: 0                        [Int]     timing/advance 游标（= #timing_cursor）
│   ├── ev_idx: 0                        [Int]     event/advance 游标（= #event_cursor）
│   ├── cmd_idx: 0                       [Int]     事件 commands 子游标
│   ├── cur_cmd: "function xxx"          [字符串]  当前待宏执行的命令（事件/击打事件共用）
│   ├── cur_note: { }                    当前生成音符（spawn_one 组装；summon 以 with storage runtime cur_note 读参数）
│   │   ├── 音符共通标签[下方链接]
│   │   ├── mapid: "new_beginning"       [字符串]  谱面 id
│   │   ├── pos_x / pos_y / pos_z        [Double]  判定位置（position 数组拆标量）
│   │   └── start_x / start_y / start_z  [Double]  起始偏移（start_pos 数组拆标量）
│   ├── cur_tp: {bpm, tpb, ...}          [复合]    当前时间点（apply 拆出，tick_rate 读 bpm/tpb）
│   └── sort_j / sort_jp1 / tmp_note     [Int/复合]  冒泡排序临时键（sort_notes 用完删除）
├── ★ 判定反馈传递（judgement_feedback → feedback 查表链）
│   ├── fb_nid: 0                        [Int]     音符 id
│   ├── fb_hitsound: 0                   [Int]     音效组号（缺省 0）
│   ├── fb_particles: 0                  [Int]     粒子组号（缺省 0）
│   ├── case_name: "spawn"               [字符串]  情况名（spawn/bad/good_early/...）
│   ├── cur_sound: "..."                 [字符串]  查表结果（音效路径，play_sound 用）

│   └── idx: 0                           [Int]     hit_events 遍历游标
```

#### 生命周期

- `start_of_game/start`：清掉 runtime 里可能残留的 `notes` / `timing_points` / `events`（防旧谱面键残留）后 merge 谱面，再写 `mapid`、`prev_gamemode`、`spawn_x/y/z`
- `init_game`：`scan_birth` 写入各音符 `_birth`，`sort_notes` 按 `_birth` 升序排序（并删除 `sort_j` / `sort_jp1` / `tmp_note` 临时键）
- `main_loop` 每刻：预置 `note_idx` / `tp_idx` / `ev_idx` 调游标递归函数；`music` 在 `time == 0` 触发播放；`bp` 每刻更新进度条
- `summon` 末尾：写 `hit_events.<id>` + 预置 `fb_hitsound` / `fb_particles` / `fb_nid` / `case_name` 调 spawn 反馈
- 判定反馈链：`judgement_feedback/*.mcfunction` 先清零再写 `fb_*`（防残留），`feedback` 查表写 `cur_sound` / `cur_particle`
- `end_of_game/stop`：清 `hit_events` 根键（`execute if data ... run data remove`）；`mapid` 存在性决定是否调 `end_of_game`

## 开始游戏

### 入口

`function rhythm_axe:play/start_of_game/start_of_game` 为通用入口
宏参数传入谱面 id；[游戏模组](#游戏模组)开关用 **mods 计分板**控制（开始游戏前 `scoreboard players set auto mods 1` 等），start 复制到 play_state 同名项

```mcfunction
function rhythm_axe:play/start_of_game/start_of_game {\
  mapid:"new_beginning"\
  }
```

### 操作检查

开始前必须**全部通过**，否则报出对应错误并终止：

- 玩家已安装[**伴侣mod**](工具组件.md#工具组件)（`mod_test` 检测）
- 进入玩家数满足谱面 `player_count`
- 当前没有已在运行的谱面（`is_running == 0`）

> 自动化的谱面格式校验尚未实现（规划见待做清单），谱面是否符合编写规范由谱师自查（见[谱面编写规范](谱面编写规范.md#谱面编写规范)）。

### 谱面读取与运行初始化

把谱面文件读取成可玩的形式（按顺序执行）：

1. **读取谱面**：宏参数取得 `mapid`，后续函数从 `rhythm_axe:maps.<mapid>` 读取字段；也可把根标签复制到运行存储（如 `rhythm_axe:runtime`）供逐刻读取
2. **运行标记**：`is_running = 1`
3. **玩家初始化**：
   - 记录玩家进入前的游戏模式（结束游戏时还原）
   - 游戏模式设为冒险
   - 回满血、给予抗性（防止环境伤害干扰游玩；游戏血量 `health` 与玩家真实血量分离，判定扣血只扣 `health`）
   - 若谱面 `teleport` 为真，传送玩家到 `spawn_pos`
   - 将实体交互距离设为 4.5 格（玩家属性 `entity_interaction_range`；结束游戏恢复 3.0）。判定距离基准 = 玩家视线位置（音符距玩家眼睛 ≤4.5 才可判定，见[音符判定](音符.md#判定)的 [^视线] 注释）
   - 给予斧头（默认小木斧，可由谱面自定义）
4. **读取全局设置**：直接使用玩家当前已保存的 options 计分板值。**开始游戏不重置全局设置**（避免玩家自定义丢失）；`reset_options` 仅在玩家主动重置时调用
5. **计分板初始化**（`init_game`）：
   - 计时器：`time = min(0, 所有音符里最早的出生时刻) - 1`（time 从“最早出生时刻前 1 刻”开始，保证能递增经过每个音符的出生时刻——包括早于音乐开始的负出生——以及 `time == 0` 的音乐起点；出生时刻 = 音符判定时间 - 基础寿命×16/流速，自动计算不再可指定）
   - 判定计数：perfect / perfect_early / perfect_late / good / good_early / good_late / bad / miss = 0
   - combo = 0、max_combo = 0
   - 血量：`health = 谱面health`
   - score = 0（最高分存于谱面 storage，结算时读写，见[结算程序](#结算程序)）
   - fc_ap = 2（初始 AP，随判定取最小）
6. **游标初始化**：`#note_cursor = #timing_cursor = #event_cursor = 0`；`#judgement_scale = 1`（由首个时间点维护）
7. **播放音乐**：`time` 推进到 0 时 `playsound` 播放谱面 `music`（time 初始 <= -1，0 必然到达），与 tick rate 同步
8. **进入主循环**：schedule 自循环调度主循环函数（每 tick 一次，见[游戏主循环](#游戏主循环)）

### 音乐播放

- 使用谱面 `music` 字段（playsound 播放），开始时机与 `time == 0` 对齐
- 与 tick rate 同步：tick rate 由红线时间点驱动（见[游戏主循环](#游戏主循环)）
- 编辑器试听用 mod 流式播放；正式游玩用 playsound

### 歌曲进度条

使用 **bossbar** 显示歌曲进度，受全局设置控制：`song_progress_display`（1=显示 0=隐藏）、`song_progress_color`（颜色，0=白 1=粉 2=蓝 3=红 4=绿 5=黄 6=紫）。

**实现要点**：
- 开始游戏时创建 bossbar：名称 = 谱面标题，颜色 = `song_progress_color`
- **只对游玩本谱面的玩家显示**：游玩玩家打统一 tag（如 `playing`），用 `bossbar set <id> players @a[tag=playing]` 控制可见性——bossbar 本身是全局资源，靠 players 列表限定谁能看到
- 每刻更新：`bossbar set <id> value <time>`、`bossbar set <id> max <end_time>`
- `song_progress_display = 0` 时不创建/隐藏
- 结束游戏时移除 bossbar；注意异常中断（如玩家中途退出）也要能清理，防止 bossbar 残留

## 游戏主循环

由 **schedule 自循环**驱动（不占用 `#minecraft:tick`）：主循环函数每次执行完，末尾用 `schedule function rhythm_axe:play/main_loop 1t` 调度自己下一次执行；`is_running == 0` 时不再调度，链条自然断开。每刻按以下顺序执行：

+ 运行检查：`is_running == 0` → 不继续调度，执行[结束游戏](#结束游戏)
+ 时间推进：`time += 1`
+ 结束点检查：若谱面定义了 `end_time` 且当前刻 == `end_time` → 立即执行结束游戏，**跳过本刻剩余处理**
+ timing_point 推进：若 `#timing_cursor` 指向的时间点 time == 当前刻 → 更新 tick rate（红线：`tick rate <bpm>bpm <tpb>`）、`#judgement_scale` 与轨道染色规则，光标+1（同一刻可能有多个）
+ 音符生成：若 `#note_cursor` 指向的音符**出生时刻 == 当前刻** → 生成该音符实体，光标+1；继续检查（同一刻可能有多个音符）。出生时刻 = `time - note_base_life*10/note_speed`（`ignore_note_speed=true` 时为 `time - note_base_life`；见[起始时间/出生时间](音符.md#起始时间出生时间)）
+ 活跃音符处理：移动、寿命更新（出生时寿命 = 基础寿命，每刻递减）、判定检测、判定保护、出窗判定；判定处理中同步 `max_combo = max(max_combo, combo)`
+ 音符判定反馈
+ events 推进：若 `#event_cursor` 指向的事件的 time == 当前刻 → 对其 `commands` 列表逐条用宏执行 `$execute positioned 0.0 0.0 0.0 run $(command)`，光标+1

### 音符生成

按 `#note_cursor` 从 storage 读取音符字段，生成一对实体（属性详见[生成](音符.md#生成)）：
- 展示实体：判定位置、`item` 按类型、tag `{mapid}_n{id}` / `map_{mapid}` / `note` / `note_display` / `note_{type}`、`transformation` 起始位置与朝向、scale 按大小
- 交互实体：起始位置、width/height 按大小、tag `{mapid}_n{id}` / `map_{mapid}` / `note` / `note_interaction` / `note_{type}`

`map_{mapid}` 是当前谱面的统一标记，用于结束游戏时按谱面精确清除全部音符实体（`kill @e[tag=map_{mapid}]`）。

生成后执行该音符 `hit_events` 中 `enabled.spawn` 为 1 的指令（宏执行）。

### 活跃音符处理

每刻对已生成的音符：

- 移动：交互实体 tp 到展示实体当前视觉位置（见[移动](音符.md#移动)）
- 寿命更新（随游戏时间递减）
- 判定检测：按类型（音符盒/木板=视线、唱片机=点击、混凝土=区域、染色玻璃=碰撞）
- 判定保护状态维护（见[判定保护](音符.md#判定保护)）
- 出窗：寿命越过判定窗口 → miss（木板直接清除自身）

判定检测、保护、等级换算的完整规则见[判定](音符.md#判定)章节。

### 音符判定反馈

> 判定反馈文件（`play/judgement_feedback/`）已实现基本反馈（物品栏上方 actionbar、聊天栏）；可自定义反馈（击打音效/击打视效/击打事件）已接入判定系统（M2-H 判定反馈组表）

各级判定种类及效果见[判定反馈](音符.md#判定反馈)。

判定反馈组表（M2-H）：

- 音效/粒子：`storage rhythm_axe:feedback` 存储表 `sounds[组][情况]` / `particles[组][情况]`（情况 = spawn/bad/good_early/perfect_early/perfect/perfect_late/good_late/miss/damage）
- 判定时按音符 `hitsound`/`hit_particles` 组号查表 → 宏执行 `$playsound` / `$particle`（改表不动函数）
- 生成时（spawn 情况）同样查表播放（在判定位置）
- hit_events：按各情况 `enabled` 过滤后宏执行指令；存储于 `storage rhythm_axe:runtime hit_events.<note_id>`，判定/清除时删除
- 实现函数：`play/feedback/`（feedback 查表入口、play_sound、play_particle、play_command、run_hit_events、hit_event、remove_events、init）

## 结束游戏

+ `is_running = 0`（主循环停止调度）
+ 清除音符实体：`kill @e[tag=map_{mapid}]`（只清当前谱面的音符，避免误删其他谱面或编辑器遗留音符）
+ 移除玩家斧头（与给予物品对应）
+ 还原玩家状态：游戏模式还原为进入前、清除抗性、视线硬编码还原为 3.0 格
+ 结算程序
+ 谱面的其他自定义指令

### 结算程序

1. 计算分数、更新最高分、把当前血量换算为百分比

> 此段内容已在 score_calculate 中实现（宏函数，end_of_game 以 with storage 调用）
> 最高分读写谱面 storage `rhythm_axe:maps.<mapid>.highest_score`（每谱面独立、持久化），
> 结算时取 max(本局分数, 历史最高) 写回；`play_state.highest_score` 仅为本局显示副本。

$ \begin{aligned}
&\mathrm{P} = \mathrm{perfect} + \mathrm{perfect\_early} + \mathrm{perfect\_late} \\
&\mathrm{G} = \mathrm{good\_early} + \mathrm{good\_late} \\
&\mathrm{M} = \mathrm{bad} + \mathrm{miss} \\
&\text{最终分数} = \frac{
    (\mathrm{P} \cdot \mathrm{1st\_weight} + \mathrm{G} \cdot \mathrm{2nd\_weight} + \mathrm{M} \cdot \mathrm{3rd\_weight})
  }{
    (\mathrm{P} + \mathrm{G} + \mathrm{M}) \cdot \mathrm{1st\_weight}
  } \cdot 100000
\end{aligned} $

## 游戏模组

游戏模组是玩家开始游戏时可选的玩法开关（如自动模式 AUTO），通过 **mods 计分板**控制：

- `load` 注册 `mods` 计分板（`mods dummy`）；玩家开始游戏前设置 `scoreboard players set auto mods 1`（0 关闭 / 1 开启）
- `start` 用 `scoreboard players operation auto play_state = auto mods` 把同名项复制到 `play_state`（运行期判定系统读取）
- `end_of_game` 结束后 `play_state.auto` 保持上次值，下次 start 会重新覆盖（无残留问题）；mods 计分板本身不被重置（玩家自定义）
- 扩展：新增 mod 时同样在 `mods` 计分板加项，start 复制同名项即可

### 自动模式 AUTO

> 键名：auto 类型：布尔（mods 计分板项）

**总语义**：玩家不能对音符进行判定，由 auto 接管——所有音符按"最佳情况"自动判定，不依赖玩家输入。

- 音符盒、木板、唱片机：**寿命 = 0 时**自动判定大 PERFECT（等价"玩家恰在完美时刻注视/击打"）
- 混凝土：自动按"所有时候玩家都在判定区域"来判定 → **每段判一次大P**（段数 = duration/density）
- 染色玻璃：不判定（玩家不操作不会撞上）→ auto 下**短路碰撞检测**（不扫掠 CCD），碰到玩家不扣血
- 击打事件（hit_events）**照常执行**（判定反馈/音效/粒子全保留——满屏 Perfect 即 AUTO 的观赏点）
- 结算时：大标题按分数正常评级；聊天栏 FC/AP 区显示 **AUTO PLAY**（加粗 aqua）；**不覆盖最高分**（`play_state.highest_score` 显示历史值，不写回谱面 storage）
- **保证判到所有音符**：auto 下全局出窗的 miss/静默清除被短路（交给 auto_note 的"寿命< -2x 补判大P"兜底）；谱面提前结束/手动 stop 时 `end_of_game` 对存活未判定音符补判大P再清除

**实现**：

- `interact_judge` 按 `auto play_state` 分流：auto=1 时音符盒/木板/唱片机 → `judgement/auto_note`（寿命=0 判大P + 出窗兜底），混凝土 → `main_concrete`（内部短路 `#in_zone=1` 逐段判P），玻璃不匹配任何分支静默跳过
- `active_note`：auto 下玻璃 `glass_sweep` 短路（`unless auto`）；全局出窗 miss/木板清除短路
- `score_calculate`：auto 不写回最高分（显示历史值）；`save_highest` 独立宏函数仅手动模式调用
- `result_display`：auto 显示 AUTO PLAY 而非 ALL PERFECT/FULL COMBO
- `end_of_game`：auto 补判（限定 `map_$(mapid)`，`as+at @s` 成对）
