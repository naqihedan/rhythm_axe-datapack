# 世界装饰

> 世界中**常驻**的装饰性动画/演出（不参与游玩判定、不与谱面挂钩）。
> **一个文件夹装一个装饰、一个装饰自包含、一篇文档记约定** —— 没有统一框架。

## 定位与边界

- **是什么**：世界里的常驻装饰表演（漂浮动效、旋转装置、环境装饰……），只要有世界就一直在演。
- **不是什么**：谱面事件（`events[]` / `hit_events`）走 `maps/<mapid>/` 那套；装饰**不绑谱面**。
- **播放模式**：**无限循环**（跑到结尾自动重来）。
- **默认不挂载**：`load` / `tick` **不为装饰留任何一行**（见下一节的理由）。
- **与游玩的关系**：**互不干扰**。装饰用独立命名空间（见[命名与隔离约定](#命名与隔离约定)）。

## ★ 为什么没有统一框架

一开始搭过一套「`init` / `reset` / `start_all` / 中央调度器」的框架（load 清场 + tick 逐刻派发）。
**已撤掉**，因为：

1. **跟本仓既有约定重复**。`load.mcfunction` 本来就是全数据包的清场处
   （`kill @e[tag=note]`、`reset * note_*`…）；`tick.mcfunction` 本来就是每刻派发处
   （`display_animation/step`、`menu/consume`、`swing_item/tick`…）。再造一层平行注册表等于把同样的事做两遍。
2. **框架本身零信息量**。真正值钱的只有三样：**文档里的约定**、**`example/` 模板**、
   以及「所有装饰实体都带 `decor` tag」这条硬约定。框架那四个文件删掉不丢任何东西。
3. **自包含更好懂**。新增一个装饰 = 建一个目录、写它自己的四个文件，**不碰任何别处**。

⇒ 所以本模板只有：**一个文件夹（`decor/<名>/`）+ 一篇文档（本文）**。

## 文件结构

```
data/rhythm_axe/function/decor/
└── <名>/                        # 一个装饰一个文件夹；自包含
    ├── start.mcfunction         # 启动/重演：建计分项 → 停旧链 → 清自己的残留 → 出生 → 设第 1 刻 → 出第 1 帧 → 排自链
    ├── frames.mcfunction        # 关键帧：只在帧首刻下发一次（守卫写精确值）
    ├── tick.mcfunction          # 驱动器：① 时钟 +1 ② 回环归位 ③ 下发帧 ④ 接着排自己
    └── clear.mcfunction         # 停演：停链 → 清自己的实体 → 清自己的时钟
```

**没有 `decor/init`、`decor/reset`、`decor/start_all`、`decor/tick`，`load` / `tick` 里也一行都没有。**

## 一个装饰的组成

| 文件 | 干什么 | 关键点 |
|---|---|---|
| `start` | 启动或**重演** | 可反复调用且幂等：先 `schedule clear` 停旧链、`reset` 清时钟、`kill` 清自己的残留，再建初态 |
| `frames` | 关键帧 | 每帧**精确值**守卫；`interpolation_duration = 帧间隔`；只写变化的属性 |
| `tick` | 逐刻驱动器 | **四段顺序不能动**：`+1` → 回环 → `frames` → 排自己 |
| `clear` | 停演 | `schedule clear` 停链 → `kill` 自己的 tag → `reset` 自己的时钟 |

## 运行机制

### 时钟与状态

- 每个装饰一个时钟：计分项 **`decor_t`**，持有者 = 假玩家 **`#decor_<名>`**。
  （**计分项由各装饰的 `start` 自己 `add`**，不依赖任何人来建。）

  | 值 | 含义 |
  |---|---|
  | `1 .. 周期` | 正在演（第几刻） |
  | `周期+1` | 触发回环（归位并重演第 1 帧） |
  | `0` / 缺省 | **未启动**（哨兵值；自链守卫据此停跑） |

### 逐刻（自链）

装饰**自己**排自己：`start` 里 `schedule function …/tick 1t` 起步，
`tick` 末尾 `execute if score #decor_<名> decor_t matches 1.. run schedule function …/tick 1t` 接力。

```
start ──schedule 1t──► tick ──┬─ ① add decor_t 1
                              ├─ ② if matches 周期+1.. run set decor_t 1     ← 回环必须在 frames 前
                              ├─ ③ function …/frames                        ← 只在下发帧首刻写 NBT
                              └─ ④ if matches 1.. run schedule …/tick 1t    ← 自链；时钟 0 时自然终止
```

- 好处：装饰**完全自包含**，跨 `/reload`、跨存档**一直活着、相位连续**（不会因 reload 重头演）。
- 代价：`/reload` **不清 `schedule`**（TimerQueue 是 SavedData）⇒ **`start` / `clear` 里必须先 `schedule clear`**
  停掉上一轮的链，否则新旧两条链各推进一次 = 每刻 `+2`、整段加速。

## 命名与隔离约定

**硬约定**（违反会出现「装饰被误杀」或「越积越多」）：

| 项 | 约定 | 原因 |
|---|---|---|
| 实体 tag | **必带 `decor`**；专属 tag 用 `decor_<名>`（如 `decor_example`） | 「所有装饰实体都带 `decor`」是唯一的全局约定；将来若要「删除某装饰」或「load 兜底清场」，靠它一条就能清全 |
| 与音符命名空间 | **绝不能蹭** `note` / `editor_note` / `map_<id>` 等 | `load` 有 `kill @e[tag=note]`、编辑器逻辑按 `editor_note` 挑选，蹭了会被误杀 |
| 时钟 | 统一计分项 **`decor_t`**，持有者 `#decor_<名>` | 名字统一便于排查（`scoreboard players get #decor_<名> decor_t`） |
| 临时存储 | storage **`rhythm_axe:decor`**（各装饰自己的键、用后即删） | 独立于 `runtime` / `prop` / `maps.editor` |
| 函数路径 | `rhythm_axe:decor/<名>/…` | 与 `maps/<mapid>` 的谱面函数完全分开 |
| 坐标 | 装饰自链里 `summon` / `kill` 一律写**绝对坐标**或用选择器，**别用裸 `~`** | 自链的上下文位置不可靠（`schedule` 唤起时命令源不在装饰处） |

## 新增一个装饰（checklist）

设新装饰名为 `<名>`（小写、下划线；例：`fountain`）。

1. **建目录** `decor/<名>/`，照 `decor/example/` 复制四个文件：
   - `start`：`scoreboard objectives add decor_t dummy`（幂等）→ `schedule clear …/<名>/tick` →
     `reset #decor_<名> decor_t` → `kill @e[tag=decor_<名>]`（**全用自己专属的东西**）→
     建初态（`summon` / `fill`，绝对坐标）→ `set #decor_<名> decor_t 1` →
     `function …/<名>/frames` → `schedule function …/<名>/tick 1t`。
   - `frames`：每个帧首刻一段，守卫写**精确值**（`matches 1` / `matches 11`…），只在帧首 merge 变化的分量。
   - `tick`：四段顺序照抄（`+1` → 回环 → `frames` → `schedule …/<名>/tick 1t`）。
   - `clear`：`schedule clear …/<名>/tick` → `kill @e[tag=decor_<名>]` → `reset #decor_<名> decor_t`。
2. **启停**：`/function rhythm_axe:decor/<名>/start` 开演；`/function rhythm_axe:decor/<名>/clear` 停演。
   **不需要改任何别处**（`load` / `tick` 都不碰）。
   - 想让它**开档自动演**？见[附：如果将来想要「每次 load 重置」](#附如果将来想要每次-load-重置)。
3. **验证**：
   - `/function rhythm_axe:decor/<名>/start` → 看动画起演。
   - 再 `/function rhythm_axe:decor/<名>/start` 一次 → 确认**没有翻倍**（实体数不增、动画不错拍）。
   - `/reload` → 确认动画**接着演**（相位连续，不重头也不消失）。
   - `scripts/check_all_macros.ps1` → 0 错误；且 `/reload` 后查 `logs/latest.log` **无 `Failed to load function`**。
4. **登记到本文档**下方[当前已登记的装饰](#当前已登记的装饰)表。

## 世界观与跨 reload 存活

因为装饰**不挂 load**，它的生命周期完全由自己掌握：

| 事件 | 装饰受到的影响 |
|---|---|
| `/reload` | 实体、计分板、`schedule`（SavedData）**全都不清** ⇒ 装饰**照常接着演**，相位连续 |
| 退出存档 / 重进 | 实体与计分板随存档持久化，**首次存档时排入的 `schedule` 队列也会持久化** ⇒ 装饰**接着演** |
| 玩家穿行 / 区块卸载 | 远处装饰实体不被 tick（服务端不 tick 远程实体），客户端也不渲染 ⇒ **不报错、不推进**；靠客户端插值补到当下应当的位置 |
| 编辑器拉高 tick rate | 装饰的「每刻」= 世界刻 ⇒ **跟着加速**（编辑器里看到装饰飞快转是正常的，不是 bug） |

## 技术选型

常驻意味着「长期一直在跑、看不到尽头」，**每刻 × 每实体的 NBT 写是最要命的开销**。按这个前提排：

| 路线 | 开销 | 何时用 |
|---|---|---|
| **关键帧 + 客户端插值**（推荐，`example` 就是这套） | 每帧只写一次，静止期 **0 写** | 绝大多数装饰 |
| 逐刻帧 + `interpolation_duration:1` | 每刻写（曲线精确可控） | 需要精确缓动（如四次缓入缓出）的少量实体 |
| `utilization/display_animation` 系统 | 每刻对每个活跃实体写 NBT | **不建议**用于常驻装饰；且它**会抹掉带固定朝向实体的朝向**，用前先读该系统的说明 |
| 装饰自己 `schedule` 自链 | 每刻 1 条 `schedule` 命令 | **本模板的口径**（自包含）；注意 `/reload` 需自己 `schedule clear` |

## 已知坑

- **自链与 `/reload` 的双链**：`/reload` 不清 `schedule` ⇒ `start` / `clear` **必须先 `schedule clear`**，
  否则新旧两条链各推进一次 = 每刻 `+2`、整段加速（已在本模板的 `start` / `clear` 里处理）。
- **回环绝不能归 `0`**：`0` 是「未启动」哨兵，落进 `0` 后自链守卫不成立 ⇒ **永久停摆且无任何报错**。
- **帧守卫写精确值，不要写区间**：`matches 1..10` 会在静止期反复 merge 同一个值 —— 每次 `data merge`
  都让客户端重启插值 ⇒ 抽搐 + 白烧指令。
- **没有「整块删 storage」这种命令**：`data remove storage <id>` 缺 path 会报
  `未知或不完整的命令 ... position` ⇒ **整个 `.mcfunction` 加载失败**（只在 `/reload` 日志里可见，
  `scripts/check_all_macros.ps1` 查不出来）。要清 storage 只能逐键 `data remove storage <id> <键>`。
- **改了 `.mcfunction` 务必 `/reload` 后查 `logs/latest.log` 的 `Failed to load function`**，别只信宏检查。
- **`schedule` 的上下文位置不可靠** ⇒ 自链里 `summon` / `kill` 写绝对坐标或选择器，别裸 `~`。
- **展示实体要被客户端追踪才更新**：装饰实体要放在**玩家常去的区域**。远处未加载区块里服务端实体不 tick，动画自然不动。
- **`block_display` 用 `block_state`（`{Name:"minecraft:white_concrete"}`），`item_display` 才用 `item`**；两者贴图朝向**不能互相参考**。
- **`view_range` 默认仅 1.0，太小** ⇒ 稍远就看不见，惯例调 `10000.0f`。
- **同刻 `summon` 太多实体会有 mspt 尖峰**（本仓实测：同刻 252 个展示实体 ≈ 700ms）⇒ 需要「大爆发」时要错峰出生。
- **带乘客（`Passengers`）的展示实体，乘客不继承父实体的 `transformation`** ⇒ 要整体位移必须逐个 merge 每个乘客。

## 附：如果将来想要「每次 load 重置」

本模板默认**跨 reload 存活**（不挂 load）。若哪天想要「每次开档/重载都重头演」，有两条路，都不需要动模板：

- **A. 手动重置**：`/function rhythm_axe:decor/<名>/start`（幂等，会先停旧链再重演）。
- **B. 恢复自动（各加 1 行）**：
  - `load.mcfunction` → `function rhythm_axe:decor/<名>/start`
  - （可选兜底）`kill @e[tag=decor]` —— 一条清掉所有装饰实体（依赖「实体都带 `decor` tag」这条约定）
