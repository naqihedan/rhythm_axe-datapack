# 工具组件

## Rhythm Axe Mod

节奏地图的必备前置模组，**并非数据包的一部分**
> waring：100% AI generate

/rhythm_axe_mod 游戏内帮助指令

### 功能

#### 增强 /tick rate 指令

原版 `/tick rate` 支持多种灵活的速率输入格式：

| 格式 | 示例 | 说明 | 范围 |
| --- | --- | --- | --- |
| 纯数字 | `/tick rate 20` | 每秒刻数 | 1 ~ 1000 |
| `数字t` | `/tick rate 30t` | 每秒刻数，带单位 | 1 ~ 1000 |
| `数字ms` | `/tick rate 50ms` | 每刻毫秒数 | 1 ~ 1000 |
| `数字bpm 数字tpb` | `/tick rate 150bpm 8` | 拍每分钟 × 每拍刻数（节奏地图专用） | 最终速率 ≤ 1000 |

##### 示例详解

| 输入 | 实际设置 | 说明 |
| --- | --- | --- |
| `/tick rate 30` | 30 tps | 每秒 30 刻，比原版快 50% |
| `/tick rate 50ms` | 20 tps | 每刻 50 毫秒（原版默认值） |
| `/tick rate 1ms` | 1000 tps | 最快速度 |
| `/tick rate 150bpm 8` | 20 tps | 适合音乐同步的常用节奏 |

##### 权限降级

原版 `/tick` 指令需要 OP 权限等级 **4**，本模组将其降为等级 **2**，使之**可被命令方块执行**。

##### 可选同步控制

在指令末尾添加 `true` 或 `false`，控制客户端是否同步服务端速率（默认为 `true`）：

| 指令 | 效果 |
| --- | --- |
| `/tick rate 30t` | 默认：客户端同步 |
| `/tick rate 30t true` | 客户端同步 |
| `/tick rate 30t false` | **客户端不同步**（仅服务端加速，客户端重置为20tps） |

##### 客户端速率同步

服务端速率超过 **20 tps** 时自动加速渲染，切换世界/离开服务器时自动重置为 20 tps。

#### Gamerule 控制 run_command 确认弹窗

自 Minecraft 25w20a 起，点击聊天/书本中的 `run_command` 会弹出确认屏幕。本模组添加了自定义 gamerule `rhythm_axe_mod:confirm_command`：

| 值 | 效果 |
| --- | --- |
| `true`（默认） | 原版行为，弹出确认屏幕 |
| `false` | 跳过确认，直接执行命令 |

```plain
/gamerule rhythm_axe_mod:confirm_command false   # 禁用确认弹窗
```

#### 音频播放控件

> /playmusic <音频路径> [起始时间] [播放速率] [目标] [音量]

|     参数     |      类型      |                 介绍                 |
|    ---      |     ---       |                 ---                  |
| `<音频路径>` |   `string`    | 和 `playsound` 一样，使用 `sounds.json` 文件内定义的声音事件 |
| `[起始时间]` | `int` @ 0..   | 从第 `<起始时间>` 刻开始播放，**单位 tick**；模组按当前服务器 tick 速率自动换算成毫秒（未编辑谱面时 20tps → 1tick=50ms），默认 0 |
| `[播放速率]` | `float` @ 0.1..8 | 音频的播放速率，**不更改音高**（保调重采样），默认 1 |
| `[目标]` |  `目标选择器`  | 要播放给的玩家，默认 `@s`（执行者） |
| `[音量]`     | `float` @ 0..1 | 音量，默认 1 |

- 如果目标对象已经有一个通过 playmusic 播放的音乐，那么新的播放任务会覆盖旧的播放任务
- 可被数据包函数直接调用（如 `playmusic rhythm_axe:rhythm_axe.audio 100 1 @s 1`）
- 执行指令时，如果没有正在编辑的谱面或者虽然有正在编辑的谱面但是谱面的BPMlist不存在，那么读取当前的服务端的mspt再换算起始时间;
- 如果有正在编辑的谱面并且谱面至少存在一个时间点，那么通过谱面的时间点信息来换算tick→起始时间
- 实现契约：模组读取 `storage rhythm_axe:maps.editor`（`{active:1b, mapid:"xx"}`）与 `storage rhythm_axe:maps.<mapid>` 的 `timing_points`（`{time,bpm,tpb,...}`）；未就绪/无时间点/数据异常时自动回退 mspt 换算

#### 🎮 可视化时间轴（编辑器 HUD 覆盖层）

编辑器打开时，屏幕顶部居中会叠加一个**黑色半透明矩形时间轴**（由 mod 的客户端 HUD 渲染，非世界内实体）。纯显示、无交互，用于直观查看谱面节奏与物件分布。

- **开关**：`options` 计分板 `editor_timeline_gui`（进编辑器时 `init_state` 置 1、退出时清 0）。1=显示，0=隐藏。
- **渲染**：`rhythm_axe_mod` 客户端 `TimelineGui`（HudElement `extractRenderState`）。横向占屏幕 70%、居中；顶部信息行 + 下方 7 条轨道行（时间点 / 事件 / 音符盒 / 木板 / 唱片机 / 混凝土 / 染色玻璃）。
- **状态栏（顶部信息行）**：一行内左/中/右三段展示，供快速查看当前曲目与节奏/速度状态：
  - **左**：`曲名 - 歌手`（`title` - `artist`）
  - **中**：`xx.xbpm 拍/每拍`（播放头所在时间点参数 `bpm`/`bpb`/`tpb`）
  - **右**：`播放速度 x 流速  播放头/结尾`（`playSpeed` + `noteSpeed`（音符流速 `note_speed`）+ `playhead/endTime`），如 `1.00x 16  500/1000`
- **格子**：固定每格 8px（不随界面尺寸变化），窗口格数 `len = 面板宽 / 8`（最小 8）。
- **播放头**：固定于窗口前 1/3 处，播放头不动、内容随谱面滚动（剪辑软件风格）。
- **平滑运动**：客户端对播放头做插值（`displayPlayhead += (playhead - displayPlayhead) * 0.15`），切换/暂停也平滑过渡，不跳变。
- **闲置淡出**：10 秒无数据变化 → 整体透明度逐渐降到 0.5（缓慢过渡）。
- **节奏刻度（节奏染色）**：按播放头所在时间点参数（`bpm`/`tpb`/`bpb`/`offset`）在上部画刻度线。染色逻辑在 `TimelineGui.rhythmColor`，**重拍优先、从粗到细**：
  - **每小节**（`(t-offset) % (tpb×bpb) == 0`）：**最粗**（`fill` 3px 宽）纯白 `0xFFFFFFFF`（小节加粗）
  - **每拍头**（拍内偏移 `r == 0`）：1px 白 `0xE0FFFFFF`
  - **细分刻**（按拍内偏移 `r = ((t-offset) % tpb + tpb) % tpb` 与 `tpb` 匹配）：

    | 段 | tpb 条件 | 命中条件 | 颜色 |
    | --- | --- | --- | --- |
    | 半拍 | `tpb % 2 == 0` | `r == tpb/2` | 红 `0xFFFF4D4D` |
    | 三连 | `tpb % 3 == 0` | `r == tpb/3` 或 `2*tpb/3` | 品红 `0xFFFF66CC` |
    | 四连 | `tpb % 4 == 0` | `r == tpb/4` 或 `3*tpb/4` | 蓝 `0xFF4DA6FF` |
    | 六连 | `tpb % 6 == 0` | `r % (tpb/6) == 0` | 紫 `0xFFB36BFF` |
    | 八连 | `tpb % 8 == 0` | `r % (tpb/8) == 0` | 黄 `0xFFFFD33D` |
    | 十二连 | `tpb % 12 == 0` | `r % (tpb/12) == 0` | 淡灰 `0xFF9E9E9E` |
    | 默认刻 | — | 其余 | 更亮灰 `0xFF8A8A8A` |

  - 匹配按 **2→3→4→6→8→12** 顺序**先命中优先**（如 `tpb=6` 时半拍的红优先于三连/六连）；所有线条随整体透明度 `alpha` 缩放（`withAlpha`），配合闲置淡出。
- **物件的显示**（来自服务端推送窗口）：
  - 时间点：红/绿混凝土（首个恒红、之后 bpm 变化为红）
  - 事件：淡蓝混凝土；**指令数 ≥2 时在格子右下角显示数量**（物品栏小数字样式）
  - 音符：按类型显示对应方块；**同一行同一刻覆盖数 ≥2 时在格子右下角显示数量**；混凝土按 `[time, time+duration]` 覆盖每格并分别统计数量
- **数据流**：服务端 `TimelineSync` 每 tick 读取工作副本 `maps.editor.history[history_cursor]`，裁剪出**窗口** `[播放头 - windowLen/3, 播放头 + 2windowLen/3]` 打包 `ShowPayload`；客户端上报当前显示长度 `ClientWindowPayload(len)`（`setWindowLen`），服务端据此设 `windowLen`。开关关闭/退出时发 `HidePayload` 清客户端。
- **逻辑判断**：播放中每 tick 推（playhead 变化）；暂停时仅在快进/快退/编辑（playhead/history_cursor 变化）时推。

## 展示实体动画系统/display animation

### 概述

对 Minecraft 展示实体（`block_display` / `item_display` / `text_display`）的
`transformation`（平移/旋转/缩放）添加**缓动动画**，支持多圈旋转和三种缓动类型。

**此功能已经在数据包内实现完毕，作为音符展示实体运动、地图装饰、谱面特效等**
**诸多有展示实体动画参与的功能的基石**

### 初始化

数据包加载时自动调用 `init.mcfunction`，无需手动操作。也可手动重载：

```plain
function rhythm_axe:load
```

或单独调用：

```plain
function rhythm_axe:utilization/display_animation/init
```

### 使用方法

#### 1. 设置全局参数（display_calc 计分板）

在调用 `start` 前，设置以下全局参数（`#ANIM_*` 存在 `display_calc` 计分板）：

```plain
# === 基本参数 ===

# 动画时长（tick），默认 20

scoreboard players set #ANIM_DURATION display_calc 40

# 缓动类型：1=缓入  2=缓出  3=缓入缓出，默认 3

scoreboard players set #ANIM_EASING display_calc 1

# 缓动幂次：1~5，默认 3（三次方）

scoreboard players set #ANIM_POWER display_calc 2

# 应用位置偏移：0=不应用  1=应用，默认 0

scoreboard players set #ANIM_APPLY_POSITION display_calc 0

# === 增量参数（起始 → 起始 + 增量）===

# 平移增量（单位：1/100 格，精度 0.01 格）

scoreboard players set #ANIM_DELTA_PX display_calc 200      # +2 格 X
scoreboard players set #ANIM_DELTA_PY display_calc 0
scoreboard players set #ANIM_DELTA_PZ display_calc 0

# 旋转增量（单位：度×1，即 360° = 360，精度 1°）

scoreboard players set #ANIM_DELTA_RX display_calc 0
scoreboard players set #ANIM_DELTA_RY display_calc 720     # 转 2 圈（720°）
scoreboard players set #ANIM_DELTA_RZ display_calc 0

# 缩放增量（单位：1/100，100 = 1.0 倍，精度 0.01）

scoreboard players set #ANIM_DELTA_SX display_calc 0
scoreboard players set #ANIM_DELTA_SY display_calc 0
scoreboard players set #ANIM_DELTA_SZ display_calc 0

# === 绝对目标参数（叠加在增量之上）===

# 若设置了 TARGET，动画终点 = TARGET + DELTA（而非 start + DELTA）

# 未设置（保持 0）则行为不变，仍用 start + DELTA

# 绝对目标平移（×100，非零即启用）

scoreboard players set #ANIM_TARGET_PX display_calc 300     # 终点平移 X = 3 格 + delta
scoreboard players set #ANIM_TARGET_PY display_calc 0       # 0=不启用，仍用 start
scoreboard players set #ANIM_TARGET_PZ display_calc 0

# 绝对目标旋转（度×1）

scoreboard players set #ANIM_TARGET_RX display_calc 0
scoreboard players set #ANIM_TARGET_RY display_calc 180    # 终点旋转 Y = 180° + delta
scoreboard players set #ANIM_TARGET_RZ display_calc 0

# 绝对目标缩放（×100）

scoreboard players set #ANIM_TARGET_SX display_calc 200    # 终点缩放 = 2.0 倍 + delta
scoreboard players set #ANIM_TARGET_SY display_calc 200
scoreboard players set #ANIM_TARGET_SZ display_calc 200
```

#### 2. 起始值覆盖（可选）

默认情况下，起始值从实体当前状态读取。如需覆盖，设置 `#ANIM_START_*`：

```plain
# 起始缩放覆盖（非零即覆盖，×100）

scoreboard players set #ANIM_START_SX display_calc 50      # 0.5 倍
scoreboard players set #ANIM_START_SY display_calc 50
scoreboard players set #ANIM_START_SZ display_calc 50

# 起始平移覆盖（非零即覆盖，×100）

scoreboard players set #ANIM_START_PX display_calc 100     # 1 格
scoreboard players set #ANIM_START_PY display_calc 0        # ← 0=不覆盖，使用实体当前 Y
scoreboard players set #ANIM_START_PZ display_calc 0

# 起始旋转覆盖（非零即覆盖，度×1）

scoreboard players set #ANIM_START_RX display_calc 45      # 45°
scoreboard players set #ANIM_START_RY display_calc 0        # ← 不覆盖，使用实体当前 Y
scoreboard players set #ANIM_START_RZ display_calc 0
```

**覆盖规则：**

| 变换 | 默认行为 | 覆盖条件 |
| --- | --- | --- |
| 平移 | 读取实体 `transformation.translation` | `#ANIM_START_PX/Y/Z` 非零时逐轴覆盖 |
| 缩放 | 读取实体 `transformation.scale` | `#ANIM_START_SX/Y/Z` 非零时逐轴覆盖 |
| 旋转 | 读取实体 `left_rotation` 四元数 → 转欧拉角 | `#ANIM_START_RX/Y/Z` 非零时逐轴覆盖 |

> ⚠ **注意**：0 表示"不覆盖，使用实体当前值"。若你确实想将起始值设为 0（如归零），可用 `1` 或 `-1` 等近似值替代。

##### 参数精度

| 参数组 | 存储格式 | 精度 | 示例 |
| --- | --- | --- | --- |
| 平移（`PX/Y/Z`、`DELTA_PX/Y/Z`、`TARGET_PX/Y/Z`） | ×100 | 0.01 格 | `100` = 1 格 |
| 旋转（`RX/Y/Z`、`DELTA_RX/Y/Z`、`TARGET_RX/Y/Z`） | 度×1 | 1° | `360` = 360°，`45` = 45° |
| 缩放（`SX/Y/Z`、`DELTA_SX/Y/Z`、`TARGET_SX/Y/Z`） | ×100 | 0.01 倍 | `100` = 1.0 倍 |

**例：只设 rx，不设 ry/rz**

```latex
#ANIM_START_RX = 45（45°）→ 覆盖 X 轴

#ANIM_START_RY = 0 → 使用实体当前的 Y 轴欧拉角

#ANIM_START_RZ = 0 → 使用实体当前的 Z 轴欧拉角
```

#### 3. 调用 main 启动

```plain
# 对 tag=anim_demo 的所有实体启动动画

execute as @e[选择器] run function rhythm_axe:utilization/display_animation/display_animation
```

调用后：

1. `main` 内部对 `tag=anim_demo` 的每个实体调用 `start`，设置起始/目标值
2. `#minecraft:tick` 每 tick 驱动 `step`，自动推进动画
3. 动画结束后 `finish` 被调用，清理实体计分板
4. `main` 自动清理全局参数 `#ANIM_*`

> 若需要对不同实体组使用不同参数（如不同的缓动类型），可直接调用 `start`：

```plain
# 为 group_a 设置参数

scoreboard players set #ANIM_EASING display_calc 1
execute as @e[tag=group_a] run function rhythm_axe:utilization/display_animation/start
```

| `#ANIM_START_RX/Y/Z` | 度×1 | 0 | 起始旋转覆盖（0=不覆盖） |
| `#ANIM_START_SX/Y/Z` | ×100 | 0 | 起始缩放覆盖（0=不覆盖） |
| `#ANIM_DELTA_PX/Y/Z` | ×100 | 0 | 平移增量 |
| `#ANIM_DELTA_RX/Y/Z` | 度×1 | 0 | 旋转增量 |
| `#ANIM_DELTA_SX/Y/Z` | ×100 | 0 | 缩放增量 |
| `#ANIM_TARGET_PX/Y/Z` | ×100 | 0 | 绝对目标平移（非零=启用） |
| `#ANIM_TARGET_RX/Y/Z` | 度×1 | 0 | 绝对目标旋转（非零=启用） |
| `#ANIM_TARGET_SX/Y/Z` | ×100 | 0 | 绝对目标缩放（非零=启用） |

#### 最终目标值公式

```plain
if TARGET ≠ 0:
    end = TARGET + DELTA
else:
    end = start + DELTA
```

| 名称 | 用途 |
| --- | --- |
| `anim_status` | 0=空闲 1=动画中 2=完成 |
| `anim_timer` | 当前步数 |
| `anim_duration` | 总步数 |
| `anim_power` | 缓动幂次 |
| `anim_easing` | 缓动类型 |
| `anim_apply_position` | 位置补偿标志 |
| `anim_start_px/y/z` | 起始平移（×10000） |
| `anim_start_rx/y/z` | 起始旋转（度×100） |
| `anim_start_sx/y/z` | 起始缩放（×10000） |
| `anim_end_px/y/z` | 目标平移 |
| `anim_end_rx/y/z` | 目标旋转 |
| `anim_end_sx/y/z` | 目标缩放 |
| `anim_cur_rx/y/z` | 当前欧拉角（step 每 tick 更新） |

### 缓动类型说明

| 类型 | 公式 | 效果 |
| --- | --- | --- |
| 1 缓入 | $ t^n $ | 慢→快 |
| 2 缓出 | $ 1-(1-t)^n $ | 快→慢 |
| 3 缓入缓出 | 前半缓入，后半缓出 | 慢→快→慢 |

$ t $ = 进度 (0~1)，$ n $ = power (1~5)

├── main.mcfunction           # 入口：调试输出 → start（所有 anim_demo 实体）→ 清理全局参数

## 数学工具/math

### 概述

## 屏幕覆盖层/camera overlay

### 概述

在玩家第一人称屏幕上绘制**覆盖整个屏幕的纹理**（斧头挥舞、进图过渡、飞溅特效等），并按帧播放动画。

### 资源包纹理

覆盖纹理放在 `assets/<命名空间>/textures/overlay/<type>/<frame>.png`：

- `<type>`：特效类型（一个子目录一种特效，如 `axe_swing`）
- `<frame>`：帧序号，从 0 开始（`0.png`、`1.png`…）
- 尺寸随意（MC 拉伸铺满屏幕），参考 640×640（局部特效）或 1280×720（全屏过渡）
- 带透明通道（PNG）

例如节奏地图的斧头挥舞：

```text
assets/rhythm_axe/textures/overlay/axe_swing/
├── 0.png ... 15.png   # 16 帧斧头挥舞序列
```

### 数据包函数

四个函数（如 `rhythm_axe:utilization/overlay/`）：

#### start（启动）

宏参数：`type`（特效类型名）、`loop`（`true` 循环 / `end` 播完结束）、`frame`（总帧数）。

```mcfunction
#arg:type,loop,frame
$data modify storage rhythm_axe:prop overlay set value {type:"$(type)",loop:"$(loop)",max_frame:$(frame)}
item replace entity @s armor.head with firework_star[item_model="rhythm_axe:empty",equippable={slot:"head",equip_sound:{sound_id:"empty"}},enchantments={binding_curse:1},tooltip_display={hide_tooltip:true}]
scoreboard players set @s overlay_frames 0
tag @s add Overlay
```

- 给玩家头盔槽塞一个带 `equippable` 的物品；`item_model` 用**空模型**（物品本身不可见，只显示 camera_overlay）
- 空模型定义 `assets/<ns>/items/empty.json`：`{"model":{"type":"empty"}}`
- `binding_curse` 防止玩家摘下头盔
- 打 `Overlay` 标签 + `overlay_frames` 计分项清零

#### tick（每 tick 驱动）

```mcfunction
execute store result score @s overlay_max_frame run data get storage rhythm_axe:prop overlay.max_frame
execute store result storage rhythm_axe:prop overlay.frame int 1 run scoreboard players get @s overlay_frames
execute if score @s overlay_frames < @s overlay_max_frame run function rhythm_axe:utilization/overlay/tick_ with storage rhythm_axe:prop overlay
execute if score @s overlay_frames >= @s overlay_max_frame if data storage rhythm_axe:prop {overlay:{loop:"true"}} run scoreboard players set @s overlay_frames 0
execute if score @s overlay_frames >= @s overlay_max_frame if data storage rhythm_axe:prop {overlay:{loop:"end"}} run function rhythm_axe:utilization/overlay/end
```

- 帧数没到 `max_frame` → 调 `tick_` 推进一帧
- 到 `max_frame`：`loop=true` 帧归零循环；`loop=end` 调 `end` 收尾

#### tick_（推进一帧）

```mcfunction
$item modify entity @s armor.head {function:"set_components",components:{"equippable":{"slot":"head","equip_sound":{"sound_id":"empty"},camera_overlay:"rhythm_axe:overlay/$(type)/$(frame)"}}}
scoreboard players add @s overlay_frames 1
```

- 把头盔物品的 `camera_overlay` 更新为第 `$(frame)` 帧纹理，帧数 +1
- `camera_overlay: "rhythm_axe:overlay/$(type)/$(frame)"` → 映射到 `assets/rhythm_axe/textures/overlay/<type>/<frame>.png`

#### end（收尾）

```mcfunction
item replace entity @s armor.head with air
tag @s remove Overlay
```

### 调用方式

```mcfunction
# 以玩家身份调用（如判定反馈时）
execute as @p run function rhythm_axe:utilization/overlay/start {type:"axe_swing",loop:"end",frame:16}
```

- 每 tick 一帧（跟游戏 tick 走）
- `loop:"end"` 播完自动收尾；`loop:"true"` 无限循环（如加载动画）
- 驱动：在 `#minecraft:tick` 或游玩主循环中，对 `@a[tag=Overlay]` 执行 `overlay/tick`

### 注意事项

- `camera_overlay` 只在**头盔槽装备**该物品时渲染，且仅第一人称可见
- 同一玩家同时只能有一个 overlay（头盔槽只有一个），新的会覆盖旧的
- 覆盖层会挡住视线：帧数别太多、持续时间别太长，播完要及时 `end`
- 判定时触发的实现：音符盒/木板/唱片机判定后，在 `judgement_feedback` 中以玩家身份调用 `overlay/start`（配合现有判定反馈）
