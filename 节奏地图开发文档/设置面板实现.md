## 定位与机制

菜单系统（`menu_click`）的页面之一，与编辑器（`editor_click`）、游玩系统并列，**三套互不干扰**。

| 项目 | 说明 |
| --- | --- |
| 入口 | `/function rhythm_axe:options/main` —— **无条件打开**（编辑中也能改设置，与总表同规则） |
| 收起 | 页脚【收起】（`15203`）；**进游戏/编辑器不自动收起**（不像总表，避免打断调参） |
| 底层存储 | 设置项仍是 **`options` 计分板**（判定权重在 `score_calculate`），**不搬 storage**。原因：mod 侧（`MusicTime`/`TimelineSync`/`RhythmAxeMusic`）同样读这两个计分板；且 `if data` **不支持范围匹配**（`matches 1..`）也**不能参与 `scoreboard players operation` 算术**，而现有引用 250+ 处 |
| UI 状态 | 与总表/房间页**共用**菜单会话 `rhythm_axe:map_list`（`open` / `panel = 22`） |
| 页号 | 按玩家存 `options_page` 计分项（**0=游玩 / 1=模组 / 2=编辑器 / 3=高级**，2026-09-30 起四页），每人独立 |
| 值的写法 | 值 = 行号×100 + 列码；布尔项列码 `1` = 切换，数值/枚举项 `1` = − / `2` = ＋ |
| 文件 | 渲染 `options/render.mcfunction` + 每页 `options/page/p{0,1,2,3}.mcfunction` + 守卫分支 `options/panel/panel22.mcfunction` + 通用叶子 `options/{num_row,bool_row,num_emit,bool_emit,footer_emit,step,step_sc,toggle,close,reset_all,reset_confirm,reset_cancel,mods_off,wrong_panel}.mcfunction` |

## 渲染链

`render.mcfunction`：清屏 → 标题 → 调当页 `page/pN` → 页脚（`map_list.panel = 22`、`enable @s menu_click` 也在这里做）。

两个**宏生成器**负责算按钮状态，输出交给**宏叶子**：

| 文件 | 角色 | 宏参 |
| --- | --- | --- |
| `options/num_row` | 数值行生成器 | `label, key, obj, lo, hi, st, blo, bhi` |
| `options/num_emit` | 数值行叶子（出 `tellraw`） | `label, key, obj, minus, plus` |
| `options/bool_row` | 开关行生成器 | `key, obj, blo` |
| `options/bool_emit` | 开关行叶子 | `label, val` |

生成器与叶子之间的参数**经专用 storage `rhythm_axe:op_ui`** 传递（`label/key/obj/lo/hi/st/blo/bhi/minus/plus/val`），不用 `function` 的 compound 参数 —— 这样 `check_all_panel_coverage.py` 的「注入型按钮值」审计（`param_keys` + `data modify set value <数字>`）才认得出 `blo`/`bhi`。

于是页文件里**一行设置项只有 5~9 条 `data modify` + 1 次调用**，不用手写一大坨 `tellraw`。

## 处理分支

| 函数 | 用途 |
| --- | --- |
| `options/toggle {key,obj}` | 布尔项翻转（1 → 0、其它 → 1）；**`obj` 必填** —— 普通设置 = `options`、模组开关 = `mods` |
| `options/step {key,delta,min,max}` | 数值/枚举项步进 + 钳制，objective 固定为 `options` |
| `options/step_sc {key,delta,min,max}` | 同上，但 objective 是 `score_calculate`（判定权重用） |

- 号段（`menu_click`）：`12201..15302`（页 0/2/3 的项）、`17001..17902`（**模组页**，独立段）、`16001..16007`（页脚，含恢复默认的确认/取消与关闭所有模组）。守卫白名单写在 `options/panel/panel22.mcfunction` 顶部两行（**三段 `unless … matches` 组合**）。
  **页脚统一用行 `160`**（2026-09-29 从 `152` 挪来）、**模组页统一用行 `170~179`**（2026-09-30 新增）—— 各页各留余量，不再和页脚撞。
- 分发在 `menu/consume`：`12201..15302` / `16001..16007` / `17001..17902` 各一条，都路由到 `options/panel/panel22`。

## 危险操作的二次确认

**【恢复默认】= 两步**（2026-09-30 加，照编辑器「删除谱面」的做法：*记 pending 状态 → 渲染确认按钮 → 确认才执行*）：

| 步 | 按钮 | 行为 |
| --- | --- | --- |
| 1 | `16004`（页脚【恢复默认】） | 只写 `rhythm_axe:map_list.reset_confirm = 1b` + 重绘（`options/reset_confirm`） |
| 2 | `16005`（【确认恢复】） | 清状态 + `options/reset_options`（`options/reset_all`） |
| — | `16006`（【取消】） | 清状态 + 重绘，**不动设置**（`options/reset_cancel`） |

`render.mcfunction` 检测到 `reset_confirm` 就把页脚换成**警告行 + 确认/取消**（两态用 `execute if/unless data storage rhythm_axe:map_list reset_confirm` 分开渲染）。状态在**打开面板**（`options/main`）、**收起面板**（`options/close`）、**确认后**（`reset_all`）三处都会清，不会残留成"下次打开还是确认态"。

**页脚末位按钮按页不同**（2026-09-30）：模组页（页 1）显示【关闭所有模组】(`16007`)，其它页显示【恢复默认】(`16004`)。实现上把页脚拆成「公共部分 `foot_head`（用 `{"text":"","extra":[…]}` 包成一个组件）+ 末位 `foot_tail`」两个 storage 键，交给宏叶子 `options/footer_emit` 输出（`$tellraw @s [$(foot_head),$(foot_tail)]`）—— 这样整行 JSON 不用写两遍。点【关闭所有模组】→ `options/mods_off`（把 `mods` 上所有开关 `set 0`；**不能用 reset**，见该文件注释）。

## 新增 / 修改一行

1. **查重** → 选行号（值 = 行号×100 + 列码；列码 `1` = −/切换、`2` = ＋）。
2. **写发射点**：在 `options/page/pN` 里按 `data modify storage rhythm_axe:op_ui …` 写参数（数值行：`label/key/obj/lo/hi/st/blo/bhi`；开关行：`label/key/obj/blo`）→ 调 `options/num_row` / `options/bool_row`（`with storage rhythm_axe:op_ui`）。
3. **写分支**：在 `panel22` 加 `execute if score #menu_value menu matches <值> run function rhythm_axe:options/step {key:…,delta:…,min:…,max:…}`（布尔项用 `options/toggle {key:…,obj:…}`）。值落在**已有号段**内则守卫不用改；开新号段才要同步两行守卫（顺带 `menu/consume` 的 `matches` 范围）。
4. **校验**：`/reload` + `scripts\check_all_macros.ps1`（0 错误）+ `python scripts\check_all_panel_coverage.py`（emit ⊆ 守卫 ⊆ 分支），再实测点一次。

## 已知坑

- ⚠️ **`bool_row` / `toggle` 的 `obj` 宏参必填**（2026-09-30 加）：漏写时宏参缺失 → **整行宏展开失败、静默无输出/无反应**（`bool_row` 漏了 → 该行不显示；`toggle` 漏了 → 点了没反应）。模组开关写 `"mods"`，其余一律 `"options"`。新增布尔行时记得三处齐全：发射点写 `obj`、分支写 `obj:`。
- ⚠️ **加新模组**：分页与号段表里的模组页用 `170~179`（列码 `1` = 切换）。新模组项写在 `options/page/p1.mcfunction`，`obj` 一律 `"mods"`，分值 `170+序号`×100+1（如第二个模组 = `17101`），并在 `panel22` 加 `options/toggle {key:…,obj:"mods"}` 分支，**再在 `options/mods_off` 里补一行 `scoreboard players set <新键> mods 0`**（【关闭所有模组】要能关掉它）—— 号段不用改守卫（`17001..17902` 已在白名单里）。`mods` 计分板的开关要在 `play/start_of_game/start` 里复制到 `play_state` 同名项才生效。
- ⚠️ **`scoreboard players add` 的 count 只收正整数**（要减必须用 `remove`）。写 `scoreboard players add <key> <obj> -1` 会**静默失败**（`/reload` 不报错，只在游戏日志里），表现就是「**减号点了数值不变**」而加号正常。正确做法：先把 `delta` 落到临时计分项 `#op_step`（`menu` 板），再用 `$scoreboard players operation $(key) <obj> += #op_step menu`（计分板运算天然支持负值，且可跨 objective）。见 `options/step` / `options/step_sc`。
- ⚠️ **生成器里含 `$(…)` 的行必须以 `$` 开头**：漏了不会报错，但宏参不展开 —— 按钮会变成字面文本 `$(blo)`、点了没反应（`check_all_macros.ps1` 会报 `has $() but no dollar prefix`）。
- ⚠️ `judge_lag_comp`（多人判定延迟补偿）⏸ **已搁置**，且 `load.mcfunction` 每次 `/reload` 都会把它强制置 0（面板里改了只在本局生效）。
